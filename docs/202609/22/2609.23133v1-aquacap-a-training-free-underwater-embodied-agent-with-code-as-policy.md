## 摘要
近年来，视觉-语言-动作模型的进展激发了人们对水下具身智能日益增长的兴趣。然而，它们对大规模交互数据的依赖限制了其在水下的适用性，因为水下数据采集成本高昂且数据稀缺。为应对这一挑战，我们提出了 AquaCap，一种用于自主水下导航与操作的免训练代码即策略框架。AquaCap 采用双层智能体，将任务指令和环境观测转化为条件感知的规划和可执行的控制程序。结构化感知随后为智能体在水下退化条件下提供语义、几何和可靠性感知的观测。失败感知记忆可诊断不成功的动作，并支持闭环重规划与代码修正。该设计无需任务特定训练或参数更新即可实现在线自适应。AquaCap 在仿真中达到 66.43% 的成功率。真实世界实验进一步展示了使用 ROV 进行自主抓取和物体运输，包括对受水动力扰动而发生位移的目标进行操作。

## Abstract
Recent advances in vision-language-action models have stimulated growing interest in underwater embodied intelligence. However, their reliance on large-scale interaction data limits their applicability underwater, where data collection is costly and scarce. To address this challenge, we present AquaCap, a training-free Code-as-Policy framework for autonomous underwater navigation and manipulation. AquaCap employs a dual-layer agent that translates task instructions and environmental observations into condition-aware plans and executable control programs. Structured perception then provides the agent with semantic, geometric, and reliability-aware observations under degraded underwater conditions. A failure-aware memory diagnoses unsuccessful actions and supports closed-loop replanning and code revision. This design enables online adaptation without task-specific training or parameter updates. AquaCap achieves a 66.43% success rate in simulation. Real-world experiments further demonstrate autonomous grasping and object transport with an ROV, including the manipulation of targets displaced by hydrodynamic disturbances.

## 1. 核心问题与研究动机

- **背景**：水下机器人对蓝色经济（海底管道/电缆巡检、海上能源设施维护、环境监测、资源勘探、深海科研）日益重要，可替代潜水员与母船作业，降低风险与成本。
- **水下环境的三大挑战**：
  - 复杂水动力（洋流、浮力、流体阻力）导致运动与控制高度不确定；
  - 能见度受限（光衰减、散射、颜色失真、悬浮颗粒）降低视觉感知可靠性；
  - 水下通信受限、低带宽，难以持续远程监督与实时数据传输。
- **现有方法的两难**：
  - **模型驱动方法**（视觉伺服、共享自治如 SHARC）依赖精确模型、仔细标定与预定义任务流程，环境/目标/机器人状态变化时难以适应；
  - **学习型方法**（AquaBot、UMI-Underwater、Bi-AQUA、OpenVLA、π0.5、GR00T N1、UnderwaterVLA、U0）需要大规模交互数据，而水下数据采集成本高昂、仿真难以复现真实条件；水下试验的布放回收成本高，反复人工干预与离线调试不现实。
- **整体含义**：论文提出 **AquaCap**——一种免训练（training-free）的 Code-as-Policy 框架，用预训练大模型在运行时将感知与控制 API 组合为可执行程序，绕开数据密集型 VLA 路线，实现水下自主导航与操作。

## 2. 方法论

### 核心思想
- 名称含义：*aqua*（拉丁语"水"）+ *Code-as-Policy*（CaP）。
- 将任务指令与观测转化为**条件感知的规划**与**可执行控制程序**，通过"规划—执行—验证—修正"闭环，仅在当前动作被验证通过后才推进任务，无需任务特定训练或参数更新。
- 三大组件：AquaCap-Agent（双层智能体）、AquaCap-Perception（结构化感知）、AquaCap-Memory（失败感知记忆）。

### AquaCap-Agent（双层 Code-as-Policy）
- **问题动机**：单管线耦合规划与编码，规划错误与实现错误难以区分，局部编码失败会破坏整个任务；且常假设生成动作按意图执行，缺乏对物理结果的验证——水下车辆漂移、目标运动、感知误差会使"程序正常结束"≠"目标达成"。
- **Policy Agent**：接收指令 *l* 与结构化观测 *o*，产出有序计划 Π。每个动作指定目标、前置条件、后置条件与时间预算，条件以布尔/数值/类别检查形式作用于观测字段（如"approach 前目标须可见，执行后须在指定距离内"）。
- **Coding Agent**：将当前动作、观测、API 文档与检索到的修正 *h* 组合为 Python 程序；经静态校验（语法、API 使用）与沙箱约束（运动限制、权限、时间预算）后执行；非法代码允许有限次重写。
- **闭环验证**：执行后重新感知，综合执行结果、传感器有效性、目标估计一致性、当前动作后置条件与下一动作前置条件进行判定；全部通过才推进。验证失败则保留当前步骤：局部修复保留动作目标只改实现，否则由 Policy 用失败证据与记忆指导重规划（如目标位移触发重新定位与对齐）。传感器故障直接停止，时间与恢复预算限定重试次数。

### AquaCap-Perception（结构化感知）
- **语义目标识别**：VLM 根据指令识别目标，提示 SAM3 分割，得到掩码、可见性与置信度，把语言指令链接到后续几何估计的对象。
- **近场几何估计**：
  - 腕部深度图中的局部表面凸起提供补充掩码；
  - 对掩码 *M* 内有效像素集合 Ω_M，用深度 D 与相机内参 K 反投影为点云：P₀ = { D(u)·K⁻¹·ũ | u ∈ Ω_M }，经深度滤波与离群点剔除得观测点集 P = {p_j}；
  - 由目标配置尺寸（长度 L、直径 d）构建参考模型点集 Q = {q_k}；对圆柱类目标先用 **PCA** 估计初始中心与主轴，再用 **ICP** 配准，迭代求解最优旋转与平移：(R̂, t̂) = argmin Σ ‖p_j − R·q_c(j) − t‖²₂；
  - 将拟合的相机系位姿变换到机器人基座系：**T̂_BO = T_BC · T̂_CO**（B、C、O 分别为基座、相机、目标系，帽子表示估计值；T_BC 由相机标定与关节构型 q 经臂运动学得到）；
  - 以收敛性、拟合质量、可见范围、掩码大小、轴向判断是否接受估计；输出目标位置与主轴（对称圆柱绕轴旋转不可观测）。
- **输出**：目标身份、距离、几何质量、相机状态、夹爪状态等结构化字段，供 Policy 与 Coding 使用，也支持失败诊断，且**不向智能体传递原始图像**。

### AquaCap-Memory（失败感知记忆）
- 每次试验开始时 M 为空；每条记录把动作与场景描述链接到结果与支撑证据；失败动作额外存储诊断原因与建议修正。
- 检索依据任务、当前动作与试验开始时生成且固定不变的初始场景描述（如目标类别、可见性）；检索记录为 Policy 提供规划建议、为 Coding 提供实现约束（如抓取失败后提示重复对齐、降低接近速度或调整夹爪闭合）。
- 修正仅指导下一次尝试，目标几何与结果验证仍由当前观测决定；**不更新模型参数**。

## 3. 实验设计

- **仿真平台**：Stonefish 模拟器，沿用 Gu 等人 [12] 的 20 个水下任务（USIM 任务套件），每方法 700 次试验。
  - 平台：BlueROV2 + Reach Alpha 5 机械臂 + Robotiq Hand-E 夹爪；仅用机载相机图像与机器人状态，不使用真值目标位姿；标有 X 的抓取任务含同类别不同颜色干扰物以考察语义目标选择。
  - 任务分布：导航 6 项（充电站、水塔、管道巡检 Pool/Sea、古船/现代船扫描）、抓取 6 项（红/蓝/pipe0/pipe1/红X/蓝X，各 80 次）、运输 1 项（浅水红色转运 40 次）、跟踪 1 项（跟随船只 20 次）。
- **真实实验**：全矢量推进 ROV + 前视 RGB 相机 + 腕部双目相机 + 夹爪位置反馈，通过厂商 SDK 执行命令；目标为**浮力自扶正物体**，会因水动力、推进器尾流与机械臂扰动持续漂移旋转；10 次抓取 + 10 次运输，全程无人工干预，每轮试验记忆初始为空。
- **对比方法**：
  - **U0** [12]：基于 USIM 训练的 VLA 模型，有目标位姿监督且支持重复抓取尝试；
  - **OpenVLA-ft**：在 USIM 数据集上微调的 OpenVLA；
  - **CaP-Agent0**（来自 CaP-X [23]）：直接评测，未做任何水下适配。
  - 所有方法在同一协议下由独立评估者评测，使用同一台笔记本。
- **评价指标**：
  - **SR**：满足任务成功标准的试验比例；抓取需目标抬升 ≥5 cm 并保持 5 s；运输还需目标在目的地 0.3 m 内保持 5 s；失败与超时计为不成功。
  - **SSR**：运输试验中抓取阶段成功的比例。
  - **SPL**（导航）、**MTD**（跟踪）、**ASD**（成功试验的平均耗时）。

## 6. 主要结论与发现

- **仿真结果**：AquaCap 总体 SR 达 **66.43%（465/700）**，比 U0（47.14%）高 19.29 个百分点；抓取 SR 61.25% 对 U0 的 36.25%。OpenVLA-ft 总体仅 7.29%，未完成任何操作任务；CaP-Agent0 在全部水下任务中成功率为 0%。
  - 作者归因：AquaCap 把操作分解为可验证阶段，用几何估计引导对齐并评估每阶段物理结果，失败时结合记忆修正后续动作或重规划，阻止执行误差跨阶段传播；OpenVLA-ft 因微调数据多样性不足难以泛化；CaP-Agent0 执行前生成动作策略、缺乏中间结果验证与在线修订，目标被水动力扰动位移后仍按过时状态执行开环动作。
  - 另注：导航 SPL（0.861 vs 0.953）与跟踪 MTD（3.85 m vs 4.34 m）上 U0 部分指标更优，AquaCap 在导航 SPL 与跟踪 MTD 上并非全面领先。
- **消融结果**：Full 65.0% > w/o Memory 52.5% > Single Agent 50.0% > VLM-based Perception 17.5%（两个管道任务全部失败）。说明**几何感知是最关键组件**；角色分离有助于保持高层任务一致性并允许局部代码修复；记忆能防止已诊断错误重复出现。
- **真实实验**：抓取与运输各 2/10 成功（SR 20%）。成功案例中，AquaCap 连续三次失败并分别诊断出"夹爪闭合不足""接近速度过快""插入过深"，逐次生成修正后第四次成功抓取，并将成功经验存入记忆用于后续运输。
- **失败分析**：多数失败被正确识别且修正与问题一致，但由于通过高层 API 控制 ROV、无法直接调节底层推进器动力学，每次运动都会产生不可预测水流，可能把未固定的浮力目标推离夹爪捕获区，导致反复定位—修正—抓取最终超时。
- **结论**：证明了免训练闭环范式（理解指令、推理任务、生成动作、评估物理结果、修正失败）在水下导航与操作中的可行性；**执行效率是主要瓶颈**，重复模型推理、感知与恢复提升可靠性但延长任务时长。

## 7. 优点

- **免训练、免参数更新**：无需任务特定策略训练或大规模水下交互数据，直接复用预训练 LLM/VLM 与感知 API，规避水下数据采集与仿真到现实迁移的难题。
- **双层智能体架构**：将高层任务规划与动作级代码生成解耦，规划错误与实现错误可分别定位，局部代码错误可在不打断整体计划的情况下修复。
- **显式物理结果验证**：以"当前动作后置条件 + 下一动作前置条件"构成感知门（perceptual gate），明确区分"程序跑完"与"目标达成"，这对水下漂移与目标运动场景尤为关键。
- **结构化、质量感知的感知管线**：语义（VLM+SAM3）、几何（深度反投影 + PCA + ICP + 手眼坐标变换）、可靠性（收敛性、拟合质量、可见范围等）三位一体；只向智能体传递结构化字段而非原始图像，兼顾可解释性与接口简洁。
- **失败感知记忆**：把诊断出的失败转化为可复用修正（规划建议 + 实现约束），在试验内即时生效，无需离线调试或重新部署。
- **实验覆盖较全面**：仿真 20 任务 / 700 次试验、消融含置信区间、真实 ROV 验证，且真实实验包含受水动力扰动持续位移的浮力目标，难度高于固定目标。

## 8. 不足与局限

- **真实场景性能明显下降**：真实 SR 仅 20%，较仿真低 41.25 个百分点，样本量仅 20 次试验，统计可信度有限。
- **底层控制能力受限**：仅通过厂商高层 API 控制 ROV，无法直接调节推进器动力学；每次运动产生的水流会把浮力目标推出夹爪捕获区，导致"高层修正正确但物理执行失败"。作者也指出需要更灵敏的目标跟踪与与底层车辆控制的更紧耦合。
