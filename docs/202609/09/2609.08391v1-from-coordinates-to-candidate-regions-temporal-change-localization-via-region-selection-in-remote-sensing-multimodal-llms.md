## 摘要
遥感多模态大语言模型（RS-MLLMs）在卫星影像的场景理解和视觉问答方面取得了进展，但定位特定目标或变化区域仍然具有挑战性。现有方法依赖生成边界框坐标作为token序列，这对于遥感中常见的小型密集目标来说较为脆弱，并且在需要同时定位多个目标时更容易出错。在这项工作中，我们提出了区域选择范式的遥感特定表述，该范式先前在自然图像MLLMs中探索过，并将其扩展到多图像序列的时间变化定位。我们的框架采用文本条件区域提议模块，将每个候选编码为带每帧视觉特征的特殊token，并融合空间和时间线索，使LLM通过在其响应中选择区域token来定位目标。我们构建了一个多任务训练与评估套件，涵盖定位、指代表达、视觉基础和跨单图像与多时相设置的理解任务。实验表明，我们的方法在时间变化定位上大幅超越坐标生成基线，同时改善单图像视觉基础并保持有竞争力的理解性能。Oracle分析分解了区域提议器和LLM选择器的贡献，提供了该框架独有的诊断性见解。我们的代码将在https://github.com/juwan-kr/RS-RegionSelect提供。

## Abstract
Remote sensing multimodal large language models (RS-MLLMs) have advanced scene understanding and visual question answering over satellite imagery, yet localizing specific objects or changed regions remains challenging. Existing approaches rely on generating bounding box coordinates as token sequences, which is fragile for the small, densely packed objects common in remote sensing and increasingly error-prone when multiple targets must be localized simultaneously. In this work, we present an RS-specific formulation of the region selection paradigm, previously explored in natural-image MLLMs, and extend it to temporal change localization over multi-image sequences. Our framework employs a text-conditioned region proposal module, encodes each candidate as special tokens carrying per-frame visual features enriched with spatial and temporal cues, and lets the LLM localize targets by selecting region tokens in its response. We construct a multi-task training and evaluation suite spanning localization, referring expression, visual grounding, and understanding tasks across single-image and multi-temporal settings. Experiments show that our approach substantially outperforms coordinate-generation baselines on temporal change localization, while improving single-image visual grounding and maintaining competitive understanding performance. Oracle analysis decomposes the contributions of the region proposer and the LLM selector, providing diagnostic insight unique to this framework. Our code will be available at https://github.com/juwan-kr/RS-RegionSelect.

### 1. 论文的核心问题与整体含义

- **背景动机**：遥感多模态大语言模型（RS-MLLMs）虽在场景理解与视觉问答上取得了长足进展，但精确定位特定目标或时间变化区域仍是核心瓶颈。
- **问题根源**：现有RS-MLLMs普遍采用“坐标生成（coordinate generation）”范式——将边界框坐标作为离散token序列输出。该范式在遥感场景中面临三重挑战：
  - 遥感目标通常体积小、分布密集，目标可能仅占据少量图像patch，微小的坐标误差即造成定位质量的显著下降；
  - 变化检测需要同时输出多个边界框，长token序列导致遗漏、重复和退化性重复模式（degenerate repetitive patterns）风险累积；
  - 坐标生成无法向LLM注入区域级视觉内容，模型需从全局特征中自行推断目标位置。
- **整体思路**：论文借鉴自然图像MLLMs中的“区域选择（region selection）”范式（如Groma、ChatRex、GPT4RoI等），将其推广到遥感多时序场景：将定位问题从“逐token生成坐标”重构为“在文本回答中直接选择候选区域token”，由预训练区域提议模块负责召回归一化为离散选择，缓解坐标生成的不稳定性。
- **核心补充**：较已有自然图像区域选择模型，该工作独特地提出了跨帧区域级特征的对齐表示——每个候选区域携带其在多时相影像中对应位置的per-frame视觉特征，使LLM可在上下文内直接进行跨时间视觉比较，这是支持时序变化定位的关键设计；同时通过统一多源检测数据集的类别词汇与提示感知类过滤，打通了开放词汇检测器与LLM之间的接口。

### 2. 方法论

#### 2.1 任务形式化与范式转变

- 给定同一地理位置的时序影像序列 I = {I₁, …, I_M} 与文本查询 q，目标是找出与 q 相关的空间区域。
- 传统方案：LLM直接输出归一化坐标 token 序列。
- 论文方案：区域提议模块先产生候选集合 R = {r₁, …, r_N}，模型在回答中通过生成特殊token（如 `<roi 4>`）完成选择。每个选择仅对应一个token而非多元组坐标，简化输出空间并提高多目标场景下的推理效率；同时每个候选的视觉特征也被注入LLM上下文，弥补了坐标生成范式下区域级视觉信息的缺失。

#### 2.2 区域提议模块（Region Proposal Module）

- **检测骨架**：采用 MM-Grounding-DINO（Swin-Tiny主干），在 Objects365、GoldG、GRIT、V3Det 预训练基础上，于五个大规模RS检测数据集（xView、DIOR、DOTA-v2.0、FAIR1M、SODA-A）微调检测头。
- **统一类别词汇**：合并五个数据集类别，形成36类开放类别空间（涵盖车辆、建筑、基础设施、体育设施等）。
- **类别条件训练**：训练时仅提供当前数据集所含类别文本，使模型学习词汇条件下的类别提议生成。
- **提示感知类过滤（Prompt-Aware Class Filtering）**：
  - 推理时将用户查询与36个类别名分别用 MiniLM 编码，计算余弦相似度；
  - 若相似度分布尖峰足够显著（最高分 > 0.35、z-score > 2.4、标准差 > 0.06，三个条件同时满足），仅保留排序靠前的类别作为检测提示，抑制无关提议；否则使用全部36类；
  - 消融显示：滤波器激活时，在建筑场景中100%保留真实类别，DIOR-RSVG中98.9%保留。
- **候选过滤**：丢弃置信度低于0.1的提议；若用户查询附带了参考框则优先加入候选并提高置信度；经NMS（IoU=0.5）去重；每样本最多保留100个候选，候选顺序在训练轮次间随机洗牌（参考框固定在列表开头）以防止位置偏差。
- **区域暴露策略**：定位/接地任务提供全部候选（供选择）；区域级QA直接引用具体区域token时仅注入相关区域以减短上下文；场景级任务（分类/通用QA）完全不给区域token。

#### 2.3 区域token表示

每个候选区域 r_k 被编码为token组：

```
<roi_k>  <obj_k,1> <obj_k,2> ... <obj_k,M>
```

- `<roi_k>`：代理token（proxy token），具有可学习嵌入，LLM通过生成它来选择该区域；
- `<obj_k,t>`：区域 r_k 在第 t 帧影像上的视觉特征token。对每帧重复提取，使LLM可直接比较同一区域的前后变化；
- 提取方式：从视觉编码器多尺度特征（NaViT层 {6, 13, 19, 26}，2×2 ROIAlign bins）应用ROIAlign，经两层MLP投影到LLM隐藏维度。

**空间提示注入**：代理token输入被增加几何描述符 g_k = [x₁, y₁, x₂, y₂, c_x, c_y, w, h, a, log(w/h)]，用于表达边界框坐标、中心、宽高、面积与长宽比：

```
e'_{<roi_k>} = LN( W_emb(<roi_k>) + α_g · GeoMLP(g_k) )
```

**时间提示注入**：每个视觉特征 token 附加帧索引嵌入 e_idx_t 与总帧数嵌入 e_cnt_M：

```
f'_{k,t} = LN( f_{k,t} + α_t · (e_idx_t + e_cnt_M) )
```

其中 α_g、α_t 为可学习标量，初始化为接近0；LN为LayerNorm。空间线索让模型感知“每个候选在哪儿/多大”，时间线索区分特征来自哪一时相。

#### 2.4 预测过程与区域感知语言建模

- LLM输入序列包含图像patch token、全部候选区域token组、系统前缀说明和用户文本查询；
- 模型输出自然语言，穿插 `<roi_k>` token 完成空间指示；
- 每个 `<roi_k>` 映射回对应边界框，形成最终定位结果；
- 由于同一候选的 pre-event 与 post-event 视觉特征均在上下文中，LLM可以在内部执行跨帧视觉比对，判断该区域是否变化、如何变化。

#### 2.5 三阶段训练策略

论文采用三阶段任务推进与参数解冻策略：

- **Stage 1（RS领域适应，2个epoch）**：只在场景级RS任务上训练（fMoW分类、GeoChat对话等），不涉及区域模块。微调LLM（LoRA，lr 2×10⁻⁵）、视觉tokenizer头部及最后一个视觉编码器模块，其余冻结。
- **Stage 2（区域提议模块与token对齐，2个epoch）**：引入RPM，LLM冻结。分为两个阶段：
  - Phase 1：仅训练区域投影器与ROI token嵌入，以学习区域token与视觉内容的关联；
  - Phase 2：激活空间几何MLP、时间嵌入、LayerNorm及α参数，扩展至多时序、多目标场景。
- **Stage 3（遥感多任务微调，2个epoch）**：在全部任务混合上联合训练全部组件（LLM经LoRA开启，lr 2×10⁻⁵，区域组件 lr 5×10⁻⁵），嵌入式更新仅限制在ROI token行，以保持预训练表示。

- **存在的公平性注意点**：TEOChat与EarthDial以其原版零样本形式被比较（部分带*标注的任务未见其训练数据），其在特定任务上偏低分属于预期内现象；零样本指标虽标注但表格无额外符号提示回归模板差异（如TEOChat用0-100坐标）。此外，DIOR-RSVG虽允许微调评估，但本模型区域提议器恰在DIOR上训练过（Table 5以‡标注了该“泄漏”），不过模型LLM/阅读部分未见DIOR训练数据，Acc指标仍具参考意义。

### 6. 主要结论

1. **区域选择在时间变化定位上带来压倒性优势**，尤其多目标场景。xBD LOC 提升37.1 F1（32.3→69.4），S2Looking CDL 提升14.1 F1。
2. **单图像语视觉接地同步受益**：DIOR-RSVG Acc@0.5 达77.3%，相较同样的坐标生成基线高约8个百分点。
3. **区域接口不损害整体理解能力**，在多数场景指标上与TEOChat齐平或超过。
4. **时序Token表示使LLM能做跨帧视觉比对**，identical-pair控制证明其行为真正受时相变化驱动（而非图外观相似作弊）。
5. **Oracle分解表明不同数据集瓶颈不同**：xBD 受提议器召回限制，LEVIR-MCI主要限制在选择器，S2Looking两端均有改进空间——这种分层诊断对坐标生成范式不可得，指引未来优化方向。
6. **推理样本时长减少4.7-5.3倍**，多目标场景输出token数大幅缩短，安全实际推理效率而非单纯增加记忆。

### 7. 优点

- **方法设计巧妙**：将自然图像区域选择范式成功迁移到遥感多时序定位，以“单token选择”代替多token坐标生成，结构性消除退化循环与长序列错误累积；
- **统一多源检测词汇**：36类合并类别空间 + 类别条件训练，使几十个不同注释体系的检测数据联合使用，提议器可在异质类别集上泛化；
- **空间/时间提示的解耦**:空间几何嵌入与时间序嵌入均以可学习缩放标量控制，机制清晰且便于消融；
- **训练流程设计合理**：三阶段课程——理解打底→区域组件对齐→联合微调——有效避免新参数不稳定；
- **诊断体系严谨**：Oracle三层次分解、identical-pair时间控制、目标密度分层、完整六配置消融，对定位框架提供坐标生成模型不可能获得的量化分析能力；
- **效率伴生增益**：输出token大减（39.1→6.4），总推理时间仍下降5倍，兼顾精度与速度。

### 8. 不足与局限

- **提议器召回率天花板**：最终定位被提议器上限所限——未进入候选集的区域不可能被选中。文中自述S2Looking CDL 与 LEVIR-MCI 均有约10-11个点的Oracle缺口。
- **训练目标与评价目标粒度不一致**：训练

训练目标与评价目标粒度不一致：训练采用逐候选回归/对比的软目标，而评价却是严格按0.5 IoU的硬命中。轻微边界偏移虽在视觉语义上仍正确，却会被判为失败，无法被容差平滑吸收。这也部分解释了Oracle F1与最终F1之间的差距来源不只来自“选错区域”，还来自“区域对但框不精”。

- **候选数量与上下文长度的隐性成本**：为保证召回率，最多输入100个候选区域，每个区域又携带若干帧的视觉token，序列可长达6000 token。虽然输出token减少、实际推理加速，但输入侧的编码与注意力开销显著高于纯坐标生成模型；对显存和批大小的约束更强，吞吐量优势主要体现在decode阶段。
- **类别词汇仍然偏窄**：36类开放词汇统一了多个检测数据集，却远非“开放世界”。场景中出现的新类别若无法被提示过滤器选中，即使视觉上醒目也无法进入候选集。提示过滤条件（0.35/2.4/0.06）虽经消融验证，仍可能把离群查询导入过窄的类别子集，从而误伤同义表达或非典型外观目标。
- **对提议器检测质量的强依赖**：区域选择范式不产生坐标，因此坐标回归误差被转移到提议器侧。两阶段级联中，训练迭代慢、梯度不可达，提议器自身仍用经典检测损失，与LLM语义之间没有端到端联系，限制了模型对“文本所关注但检测器未召回”目标的纠错能力。
- **实验覆盖的时相与传感器多样性有限**：xBD与S2Looking均为双时相高分辨率RGB卫星/航拍图像。QFabric虽带来2–5帧与多种传感器来源，但训练分布仍以Visible光为主；对SAR、多光谱等异质模态、跨时相配准误差大或重访间隔变化大的真实场景泛化尚未充分验证。
- **数据集同源语义的局限**：HRCUS-CD被用于零样本评估是亮点，但其余多数数据集共享相近的“建筑/道路/车辆”语义空间，提示过滤器对这个语义空间可能过拟合。自然图像类别的零样本接地、罕见灾损形态或非标准地理目标仍缺少直接证据。
- **统计严谨性有待加强**：结果未提供多次随机种子实验的方差或显著性检验；多组对比中不同基座、不同参数量与不同零样本设置并存，虽已用Ovis2.5-FT做了理想受控对照，但对其他模型的差异解释仍需谨慎。
- **辅助任务覆盖不全**：区域级视觉问答（如QFabric RTQA）仅覆盖“是否存在与何时变化”的层面，尚未探索“哪个候选发生了何种具体变化”的细粒度描述式输出；序列表征虽然为跨时相推理提供了条件，却没有专门任务来激发其叙事性表达能力。

**总体而言**，该论文以“候选选择替代坐标生成”为主线，完成了从检测器候选生成、跨时相区域特征编码、空间/时间提示注入到三阶段训练的系统化构建，并以多组高质量诊断实验证明该范式在密集多目标时序定位上的结构性优势。它将自然图像MLLM中“区域即token”的思想推广到遥感时序领域，并对此进行了针对性的时序扩展，为后续RS-MLLM在精细空间推理方向上的研究提供了清晰且可复现的方法学参考。其主要短板——提议器召回瓶颈、开放词汇受限与评估覆盖的传感器类型不足——为后续工作留出了明确的改进空间。该文的技术价值和诊断思路都值得进一步借鉴。
