## 摘要
近期大语言模型和多模态模型的进展，将遥感（RS）处理从简单的感知模型推进到旨在解决复杂、长时序遥感任务的智能体系统。然而，现有系统往往依赖单一化的决策框架，无法适应遥感任务多阶段、相互依存的特性。这种集中式方法导致了任务执行不稳定、工具使用错误以及跨阶段误差传播等挑战。为解决这些问题，我们提出了HiRS-Agent，一种用于长时序遥感任务求解的分层多智能体系统。HiRS-Agent采用两层协作架构：管理层（Manager Layer）负责动态路由、步骤级验证、重规划与终止控制，而专家层（Specialist Layer）依据遥感工作流组织领域特定工具，并承担子任务推理与工具执行。为进一步增强系统能力，我们引入两阶段监督微调策略及验证引导的分层强化学习阶段，以联合优化协调与工具使用策略。在Earth-Agent Benchmark和ThinkGeo上的实验表明，HiRS-Agent显著提升了长时序工具使用能力与最终任务正确性，验证了结构化多智能体协作对构建可靠遥感智能体的有效性。代码已公开于https://github.com/IntelliSensing/HiRS-Agent。

## Abstract
Recent advances in large language models and multimodal models have pushed remote sensing (RS) processing from simple perception models to agentic systems designed to tackle complex, long-horizon RS tasks. However, existing systems often rely on monolithic decision-making frameworks, which fail to accommodate the multi-stage, interdependent nature of RS tasks. This centralized approach leads to challenges such as unstable task execution, incorrect tool usage, and error propagation across stages. To address these issues, we propose HiRS-Agent, a hierarchical multi-agent system for long-horizon RS task solving. HiRS-Agent adopts a two-level collaborative architecture: the Manager Layer handles dynamic routing, step-level verification, replanning, and termination control, while the Specialist Layer organizes domain-specific tools according to the RS workflow and is responsible for subtask reasoning and tool execution. To further enhance the system's capability, we introduce a two-stage supervised tuning strategy and a verification-guided hierarchical reinforcement learning stage to jointly optimize coordination and tool-use policies. Experiments on Earth-Agent Benchmark and ThinkGeo show that HiRS-Agent substantially improves long-horizon tool-use capability and final-task correctness, demonstrating the effectiveness of structured multi-agent collaboration for reliable RS agents. The code is publicly available at https://github.com/IntelliSensing/HiRS-Agent.

### 1. 核心问题与研究动机

- **背景演进**：遥感（RS）分析正从传统的单次感知模型（如 VQA、目标检测、分割）向能够自主执行复杂任务的长时序智能体系统演进。真实遥感任务往往需要多步推理、工具调用、中间结果判读与迭代决策。
- **核心困难**：现有遥感智能体多由通用智能体范式改编而来，未能围绕遥感工作流的内在结构设计，导致在**长时序、多阶段、强上下游耦合**的任务中可靠性不足。以洪水制图为例，早期将云阴影误判为水体会直接污染下游水体指数计算、淹没区估算与最终报告。
- **三大失配**（论文核心动机）：
  - **工作流失配（Workflow mismatch）**：遥感任务遵循结构化处理链，但现有通用智能体设计未显式建模阶段依赖或长时序工作流组织。
  - **知识失配（Knowledge mismatch）**：作为智能体"大脑"的 LLM 未充分对齐遥感专业知识，无法真正理解物理机制、光谱约束与专业数据处理流程。
  - **控制失配（Control mismatch）**：现有框架强调局部动作选择或最终答案评估，对中间状态验证与执行失败的恢复支持不足。
- **总体断言**：仅靠扩大模型规模不足以解决长时序遥感任务的可靠性问题，必须显式建模遥感工作流结构与阶段依赖关系。

### 2. 方法论

HiRS-Agent 包含三大核心组件：**分层多智能体架构**、**两阶段专家-工作流对齐微调（Expert-tuning）**、**验证引导的分层强化学习（VG-HRL）**。

#### 2.1 分层多智能体架构（Hierarchical Agent Architecture）

- **整体结构**：两层协作系统——Manager Layer（管理层）+ Specialist Layer（专家层）。
- **共享参数策略**：所有角色共享同一 LLM 骨干和 LoRA 适配器，仅通过角色提示词区分（prompt-conditioned role instantiation），记作策略 $\pi_\theta$。

##### Manager Layer（Orchestrator Agent, OA）

- **结构化全局状态**：$s_t = \{x, d, g_t, H_t, C_t\}$
  - $x$：用户指令；$d$：多模态遥感输入数据；$g_t$：当前子目标；$H_t$：结构化全局记忆；$C_t$：动态约束。
- **全局记忆（Global Memory）**：$H_t$ 是可查询的结构化记忆，存储四类信息：任务上下文、路由状态、执行轨迹、中间证据。
- **路由与控制决策**：$(\tau_t, c_t) \leftarrow \pi_\theta(s_t; \rho_{OA})$，其中 $\tau_t$ 选择专家代理，$c_t$ 决定下一动作（继续/重规划/验证/终止）。
- **历史感知验证**：OA 先从全局记忆中检索相关信息 $m_t = \text{Retrieve}(H_t, g_t, C_t)$，再输出验证结果：
  $$z_t = V(g_t, o_t, C_t, m_t) \in \{\text{pass}, \text{uncertain}, \text{fail}\}$$
- **三类验证检查**：
  1. **模式有效性（Schema validity）**：必需字段与类型是否满足；
  2. **子目标一致性（Sub-goal consistency）**：输出是否推进或完成当前目标；
  3. **约束满足（Constraint satisfaction）**：物理一致性（反演关系是否有意义）、光谱正确性（波段使用与指数计算是否恰当）、统计合理性（聚合模式与输出分布是否合理）。
- **自适应控制**：FAIL → 失败重规划（工具修复、替代路由、子目标调整）；UNCERTAIN → 交叉检查（重新执行或替代推理路径）；PASS → 结果写入记忆并推进。所有中间结果（包括失败与恢复轨迹）均存入 $H_t$，保证后续决策的历史感知性（history-aware），避免短视决策。

##### Specialist Layer（专家层）

- **按遥感工作流功能递进划分三个专家族**（从光谱解析到物理反演再到统计分析）：
  - **Surface Parsing Agent（SPA，地表解析代理）**：面向感知与解析类子目标——目标检测、分割、ROI/掩膜生成、NDVI/NDWI 等光谱指数计算。工具涵盖视觉解析、空间区域处理、指数计算原语。典型失败模式：云/阴影干扰、边界模糊、跨模态空间错位。
  - **Physical Retrieval Agent（PRA，物理反演代理）**：面向物理反演与定量产品生成（如地表温度 LST 反演）。工具涵盖物理反演算子、辐射定标与归一化、质量控制。典型失败模式：单位/量程不一致、大气伪影敏感、低质量观测下估计不稳定。
  - **Statistical Analytics Agent（SAA，统计分析代理）**：面向数据聚合与清洗、统计检验与相关分析、报告级指标计算与对比。工具涵盖表格/时间序列处理、统计推断、中间产物的受控文件 I/O。典型失败模式：中间输出模式不匹配、缺失值传播、检验假设被违反。
- **工具分区设计**：总共 120 个工具，SPA 42 个、PRA 18 个、SAA 60 个（按图 2 信息）。分区可降低跨域混淆，提高执行可靠性。

#### 2.2 两阶段监督微调：Expert-tuning

**目的**：解决知识失配——将通用 LLM 对齐到遥感专业知识与可执行处理流程。

##### Stage I：基础知识对齐

- 构建三层级遥感知识体系：3 个 L1 主题、11 个 L2 模块、28 个 L3 领域，覆盖"遥感基础"、"数字图像处理"、"智能解译与应用"。
- 从四本权威遥感教材中提取内容，经内容抽取→归一化→分块→改写→标注五个阶段构建 **RS-EXPERT 语料库**，最终得到 **1,583 个语义连贯知识块**、**5,687 个知识导向训练样本**。

##### Stage II：工作流对齐

- 从真实遥感应用流水线（多智能体演示日志 + 两位专家验证）构建工作流监督数据，聚焦"数字图像处理"与"智能解译与应用"两个分支。
- 两种数据格式：**Workflow MCQ**（选择正确处理方案，684 个）和 **Workflow Order**（还原工具使用序列，309 个），共 **993 个样本**，覆盖 14 个任务族。
- 80% 数据转为指令-响应对训练，20% 留作评估。
- 构建 **RS-EXPERT-BENCHMARK** 评测知识获取与工作流泛化能力，含域内（1,334 条）与域外（4,250 条，来自未见过的 RS 手册）双域划分，并做了选项长度偏差与难度校准。

#### 2.3 验证引导的分层强化学习（VG-HRL）

**目的**：超越模仿学习，联合优化全局编排与局部工具执行。基于 GRPO（Group Relative Policy Optimization）实现。

##### 分层奖励设计

- **管理层奖励（轨迹级）**：
  $$R_{mgr} = \omega_{route}\hat{R}_{route} + \omega_{final}\hat{R}_{final} + \omega_{len}\hat{R}_{len}$$
  其中 $\hat{R}_{route}$ 是归一化路由正确性，$\hat{R}_{final}$ 是归一化最终任务成功率，$\hat{R}_{len}$ 惩罚过长轨迹。
  
- **专家层奖励（步骤级，领域感知分级门控奖励）**：
  $$R_{spec,k}^{(i)} = \begin{cases} -1.0 & \tau_k = 0 \\ -0.5 + 0.2R_{exec} & \tau_k = 1 \\ 0.5 + 0.2R_{exec} + 0.3\hat{R}_{args} & \tau_k = 2 \end{cases}$$
  其中 $\tau_k = 0/1/2$ 分别对应 Tier 1（幻觉的域外工具）、Tier 2（错误但域内工具）、Tier 3（正确工具）；$R_{exec} \in \{-1, 0, +1\}$ 为原始执行反馈；$\hat{R}_{args} \in [0,1]$ 为归一化参数质量分（仅在工具正确时计算）。该奖励区分"幻觉域外工具"与"语义更接近的域内错误"，保留组内方差以稳定相对优化。

##### 角色感知的分组优化

- **管理层优势**：同任务的 $G$ 条完整轨迹构成一组，按轨迹级奖励计算组内相对优势 $A_{mgr}^{(i)}$。
- **专家层优势**：按 **（任务, 步骤索引）** 分组，使同一执行位置的工具调用互相对比：
  $$A_{spec,k}^{(i)} = \frac{R_{spec,k}^{(i)} - \text{mean}(\{R_{spec,k}^{(j)}\}_{j=1}^G)}{\max(\text{std}(\{R_{spec,k}^{(j)}\}_{j=1}^G), \epsilon_{th})}$$
  $\epsilon_{th}$ 为低方差组回退阈值。
- **混合损失**：两个层次仅在损失层合并（非奖励层），保持各自归一化与优化动态稳定：
  $$\mathcal{L}_{mixed} = \lambda \mathcal{L}_{mgr} + (1-\lambda)\mathcal{L}_{spec}, \quad \lambda = 0.5$$
- **算法主流程**（Algorithm 1）：对每个任务采样 $G$ 条完整轨迹 → 分别计算管理层/专家层奖励 → 分别按对应分组估计优势 → 累积两个损失 → 以混合损失更新共享策略。

- **分层架构显著提升长时序工具使用能力**：在 Earth-Bench 上，搭载 Qwen3-4B 的 HiRS-Agent 将 Accuracy 从 15.73/10.08 提升到 43.95/45.56；Tool-Exact-Match 从 0.00/8.63 提升到 31.67/34.64；Param-Match 从 0.00/4.21 提升到 19.54/20.81；Efficiency 也同步改善（轨迹更短）。Qwen3-8B 也有类似增益（Accuracy 达 48.39/53.62）。

- **训练策略有效且不牺牲通用能力**：Expert-tuning 使 RS-EXPERT-BENCHMARK 总分从 73.35 提升至 87.60（Qwen3-4B），同时 MMLU-Redux 几乎不变，MATH-500 与 Multi-IF 仅有少量下降，表明"专业化-通用性保持"之间取得良好平衡。
- **架构与训练互补**：消融实验表明，验证机制提供主要增益（Exact 从 6.84 提升到 29.05），RS 专家分层进一步将 Accuracy 提升至 43.95/45.56；Expert-tuning 与 VG-HRL 依次叠加带来持续提升。
- **核心主张**：结构化多智能体协作机制 + 显式遥感工作流建模，比单纯扩大模型规模更能带来可靠的执行效果。即便是 4B 轻量开源骨干，在某些评测设置下也能超过最强的闭源模型。

### 7. 方法亮点

1. **针对性强的三大失配诊断**：清晰归纳了现有遥感智能体在长时序任务中的核心问题（工作流/知识/控制失配），方法设计逐一对症下药，逻辑链条完整。
2. **领域特化的分层架构**：Manager–Specialist 双层结构与遥感处理链（光谱解析→物理反演→统计解析）天然对齐，工具按阶段分组，比通用扁平 Agent 或按人类社会角色划分的多智能体系统更契合领域依赖结构。
3. **验证机制具备遥感约束意识**：将物理一致性、光谱正确性、统计合理性编码进验证函数，验证结果（pass/uncertain/fail）驱动自适应控制（提交/交叉检查/重规划），且所有中间状态（含失败）都存入结构化记忆——这个闭环设计对抑制遥感任务中典型"早期小错、晚期大错"的误差传播至关重要。
4. **分层奖励 + 分层优势估计**：管理层按轨迹、专家层按（任务，步骤索引）分组计算相对优势，避免粗细粒度信号混叠；专家层奖励的三级分级（域外幻觉/域内错误/正确工具）保留组内梯度信息，比二元失败门控更利于稳定优化。
5. **共享骨干 + 提示词区分角色的工程实践**：无需运行多个独立模型实例，训练与推理开销较低（4B 仅需 2 张 4090），实用性强。
6. **评测体系完整**：同时覆盖工具使用质量、参数匹配、效率、端到端正确性、知识获取、工作流泛化、通用能力保持等维度。
7. **领域适应数据构建严谨**：RS 知识体系具备四本权威教材来源、三层级知识体系标注，还专门做选项长度偏差和难度校准，体现了对评测质量本身的关注。

### 8. 不足与局限

1. **推理/部署隐忧**：层级结构每次执行需多次调用 LLM（管理层的路由+验证+子目标分解，专家层的工具推理），即便共享骨干，实际推理开销可能是普通单轮调用的数倍以上。文中 Efficiency 指标只反映工具调用次数/轨迹长度，未报告真实延迟或 API 成本。
2. **外部评测

2. **外部评测与自建基准的覆盖有限**：Earth-Bench 与 ThinkGeo 本质上是通用地理空间/遥感智能体评测集，主要考察工具调用轨迹和最终答案正确性，未必能代表遥感领域真实任务中复杂的物理约束、多源数据协同与专业判读习惯；自建的 RS-EXPERT-BENCHMARK 采用多项选择题形式，更多检验知识记忆与简单工作流推断，难以完全替代对端到端决策质量的评估。此外，域外测试集来源于未见的遥感手册，仍属同质化文本知识范畴，对跨传感器、跨区域、跨任务类型的分布漂移泛化能力验证不足。

3. **训练数据规模与标注可靠性存疑**：工作流监督数据仅有 993 条（684 条 MCQ + 309 条 Order），覆盖 14 个任务族，相较遥感工作流的真实多样性仍显稀疏，模型对未见任务族的工作流泛化可能依赖任务间共性而非真正的领域理解；知识对齐阶段依赖两位专家人工标注与验证，但论文未报告标注者间一致性系数，也未说明一旦出现标注分歧时的处理规则。另一方面，RL 阶段同时使用工具执行反馈与人工验证轨迹，若监督数据中存在系统性偏差，强化学习可能进一步放大而非纠正这种偏差。

4. **奖励与超参数设计引入较多人工先验**：VG-HRL 中专家层三级分级奖励的阈值（0/1/2）、各分量权重、低方差回退阈值 $\epsilon_{th}$、管理层/专家层混合系数 $\lambda=0.5$ 均依赖人工设定，论文未报告敏感性分析。Tier 分级依赖“工具是否域内”的先验功能分组，但域内/域外的边界在任务族之间可能不一致，这会导致部分正确工具获得奖励偏差；此外，参数质量分 $\hat{R}_{args}$ 只覆盖正确的工具调用，使训练信号的质量分与执行反馈分布不均衡。

5. **验证机制本身缺少独立评估**：设计中的“物理一致性 / 光谱正确性 / 统计合理性”验证函数是规则的启发式与 LLM 判断的混合，其自身准确率、召回率、误判率均未单独评测。若验证器本身对中间状态产生系统性误判（如将真实的水体反演结果判为 fail），自适应控制反而可能引入错误恢复路径，论文未能区分“验证器提升了智能体策略”与“验证器自身很强”两种解释；UNCERTAIN 状态触发的交叉检查也可能带来额外延迟或陷入循环，文中未分析此类情况的频率与代价。

6. **对比实验的解释力与统计严谨性不足**：未报告多次随机种子的均值与标准差，也未提供显著性检验，关键结论（如超过 GPT-5/Gemini-2.5）可能受单次运行噪声影响；部分对比方法沿用官方默认提示词而非针对当前任务做充分适配，对闭源模型还无法完全控制推理温度与后处理细节；“Generic+V”消融在 Accuracy 等指标上出现非单调提升，论文解释较简略，削弱了“分层架构带来可预测增益”的论证强度。

7. **推理成本与工程落地未被量化**：分层架构每次执行需要多次调用 LLM（管理层路由、子目标分解、验证、重规划，专家层工具推理），实际端到端延迟远高于单次调用模型。文中 Efficiency 指标只反映工具调用次数，未报告 GPU 推理耗时、API token 成本或端到端 wall-clock 时间；在与闭源模型对比时，也未折算总推理成本，导致“轻量模型超越闭源大模型”的成本-性能权衡缺乏定量证据。

8. **中长期稳定与维护问题未讨论**：知识对齐语料来自四本权威教材，时间快照属性强，而遥感技术（新传感器、新指数、新反演算法）演进迅速，知识库与工具注册表如何增量更新？工具数达 120 个，工具命名与参数规范依赖人工设计，当工具集合扩展时，LLM 路由和验证函数的适应性未经测试；此外，论文未公开代码、模型权重、基准数据或可复现实验配置，对后续研究者复现与扩展形成客观障碍。

总体而言，HiRS-Agent 在问题诊断、架构设计、训练策略与评测体系上均体现出高水平系统性，其“分层编排 + 遥感知识对齐 + 验证引导强化学习”的组合思路对领域智能体研究有较强参考价值。但其验证器可靠性、奖励先验敏感性、推理成本与统计严谨性等短板，仍需更详尽的实验与公开资源来支撑其长期稳健性主张。
