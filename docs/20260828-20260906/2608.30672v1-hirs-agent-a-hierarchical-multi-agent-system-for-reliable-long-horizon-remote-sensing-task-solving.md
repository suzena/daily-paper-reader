## 摘要
近年来，大语言模型和多模态模型的进展已推动遥感（RS）处理从简单的感知模型发展为旨在解决复杂、长时程遥感任务的智能体系统。然而，现有系统通常依赖单一化决策框架，无法适应遥感任务的多阶段、相互依赖的特性。这种集中式方法导致任务执行不稳定、工具使用错误以及跨阶段错误传播等挑战。为解决这些问题，我们提出了HiRS-Agent，一种用于长时程遥感任务求解的分层多智能体系统。HiRS-Agent采用两级协作架构：管理层负责动态路由、步骤级验证、重新规划与终止控制，而专门层根据遥感工作流组织领域特定工具，并负责子任务推理与工具执行。为进一步增强系统能力，我们引入了两阶段监督微调策略和验证引导的分层强化学习阶段，以联合优化协作与工具使用策略。在Earth-Agent Benchmark和ThinkGeo上的实验表明，HiRS-Agent显著提升了长时程工具使用能力与最终任务正确性，证明了结构化多智能体协作对于构建可靠遥感智能体的有效性。代码已公开于https://github.com/IntelliSensing/HiRS-Agent。

## Abstract
Recent advances in large language models and multimodal models have pushed remote sensing (RS) processing from simple perception models to agentic systems designed to tackle complex, long-horizon RS tasks. However, existing systems often rely on monolithic decision-making frameworks, which fail to accommodate the multi-stage, interdependent nature of RS tasks. This centralized approach leads to challenges such as unstable task execution, incorrect tool usage, and error propagation across stages. To address these issues, we propose HiRS-Agent, a hierarchical multi-agent system for long-horizon RS task solving. HiRS-Agent adopts a two-level collaborative architecture: the Manager Layer handles dynamic routing, step-level verification, replanning, and termination control, while the Specialist Layer organizes domain-specific tools according to the RS workflow and is responsible for subtask reasoning and tool execution. To further enhance the system's capability, we introduce a two-stage supervised tuning strategy and a verification-guided hierarchical reinforcement learning stage to jointly optimize coordination and tool-use policies. Experiments on Earth-Agent Benchmark and ThinkGeo show that HiRS-Agent substantially improves long-horizon tool-use capability and final-task correctness, demonstrating the effectiveness of structured multi-agent collaboration for reliable RS agents. The code is publicly available at https://github.com/IntelliSensing/HiRS-Agent.

## HiRS-Agent 论文详细总结

### 1. 核心问题与整体含义（研究动机和背景）

遥感（Remote Sensing, RS）领域正经历从“简单感知模型”向“可执行智能体系统”的范式转变。现实世界中的遥感任务（如土地利用变化分析、洪水制图、城市扩张趋势追踪）往往涉及多步骤推理、工具调用、中间结果解读和跨阶段的迭代决策，远超一次性感知任务的范围。然而，现有遥感智能体系统普遍存在以下三个核心不匹配问题：

- **工作流不匹配（Workflow Mismatch）**：遥感任务具有内在的多阶段、强耦合流程（如从光谱解释→物理反演→统计分析），但当前系统多直接套用通用智能体范式，未能显式建模阶段间的依赖关系。
- **知识不匹配（Knowledge Mismatch）**：充当智能体“大脑”的大语言模型缺乏对遥感物理机制、光谱约束和专业数据处理流程的深度对齐。
- **控制不匹配（Control Mismatch）**：现有框架偏重局部动作选择和最终答案评估，缺乏对中间状态的验证和失败恢复机制，导致早期错误跨阶段传播累积。

论文明确指出，遥感任务中早期阶段的错误（如将云阴影误识别为水体）会直接级联影响下游的水体指数计算、淹没区域估算和最终报告，因此系统对中间结果的物理、光谱和空间一致性约束极为敏感。这些问题的根源在于缺乏围绕遥感工作流内在结构设计的层次化组织和验证引导的可靠性控制。

### 2. 论文提出的方法论：核心思想与技术细节

#### 2.1 整体框架：两级层次化多智能体系统（HiRS-Agent）

HiRS-Agent 围绕遥感任务“光谱解析 → 物理反演 → 统计分析”的规范处理链设计两级协作架构，核心思路是将全局规划控制与领域专业执行分离。

**Manager Layer（管理层）**——由一个编排智能体（Orchestrator Agent, OA）实例化，负责：

1. **任务分解与路由**：将用户指令分解为子目标，并路由至相应专业智能体。
2. **全局结构化记忆**：维护全局状态 $s_t = \{x, d, g_t, H_t, C_t\}$，其中 $H_t$ 是结构化可查询的记忆，存储任务上下文、路由状态、执行轨迹和中间证据，用于显式建模跨阶段的长程依赖。
3. **历史感知的步骤级验证**：验证器 $z_t = V(g_t, o_t, C_t, m_t)$，输出为 `pass / uncertain / fail` 三类判定，执行三重互补检查：模式有效性（字段和类型是否满足）、子目标一致性（输出是否推进当前目标）、约束满足性（结果是否符合物理/光谱/统计合理性）。
4. **验证引导的自适应控制**：`FAIL` 触发失败重规划（工具修复、替代路由或子目标调整）；`UNCERTAIN` 触发交叉验证或替代推理路径；`PASS` 则将结果提交至记忆并推进流程。

**Specialist Layer（专家层）**——按遥感工作流阶段组织的三类专业智能体：

- **Surface Parsing Agent（SPA，地表解析智能体）**：处理目标检测、分割、ROI生成及光谱指数解析类子目标，工具涵盖视觉解析、空间区域处理和指数计算。
- **Physical Retrieval Agent（PRA，物理反演智能体）**：处理物理量反演任务（如LST反演、定量产品生成），工具涵盖物理反演算子、辐射定标归一化和质量控制。
- **Statistical Analytics Agent（SAA，统计分析智能体）**：处理数据聚合、统计检验、相关性分析和报告级指标计算。

三者在共享参数架构下由角色提示词区分，各有侧重工具子集（42/18/60个工具），减少跨域混淆。

#### 2.2 Expert-to-Workflow Alignment Tuning（Expert-tuning）

为了解决知识不匹配问题，设计两阶段监督微调策略：

- **Stage I：基础知识对齐**——基于遥感权威教材构建三级知识体系（3个L1主题、11个L2模块、28个L3领域），经内容抽取、归一化、分块、重写和标注流程生成 1,583 个知识块和 5,687 个知识监督样本。
- **Stage II：工作流对齐**——从真实遥感应用流程和智能体日志构建工作流监督数据，包含684个Workflow MCQ（选择正确流程方案）和309个Workflow Order（恢复工具序列）样本，覆盖14个任务族，将知识体系与可执行流程对接。

#### 2.3 Verification-Guided Hierarchical RL（VG-HRL）

基于GRPO实现，核心是跨层级的分层奖励设计和角色感知分组优化，以在损失层面联合优化双层级策略：

- **管理层轨迹级奖励**：$R_{mgr} = \omega_{route}\hat{R}_{route} + \omega_{final}\hat{R}_{final} + \omega_{len}\hat{R}_{len}$，评估路由正确性、最终任务成功率和轨迹长度惩罚；同一任务的所有rollout形成一个组，计算组内相对优势。
- **专家层步骤级分级奖励**：区分三级工具调用——$\tau_k=0$（幻觉的领域外工具，奖励-1.0）、$\tau_k=1$（错误但领域内工具，-0.5+0.2R_exec）、$\tau_k=2$（正确工具，0.5+0.2R_exec+0.3R_args）；按（任务，步骤索引）分组计算优势，以便在同一执行位置上比较不同的工具调用。
- **混合损失**：$L_{mixed} = \lambda L_{mgr} + (1-\lambda)L_{spec}$，默认$\lambda=0.5$。关键设计是仅损失层而非奖励层融合，保持两层独立归一化与稳定训练。

### 6. 主要结论与发现

1. **层次化架构显著提升小规模开源模型表现**：以Qwen3-4B为例，Earth-Bench Accuracy从约15.73/10.08提升至43.95/45.56（AP/IF），超过部分大模型闭源模型；ThinkGeo上Ans指标甚至优于所有对比模型（包括GPT-4o等）。
2. **结构化协同比模型规模更重要**：从4B扩展至8B时，HiRS-Agent（8B达48.39/53.62 Accuracy）进一步缩小了与专有模型的差距，说明显式的遥感工作流结构建模是提升可靠性的关键，而非单纯扩大参数规模。
3. **Expert-tuning实现专业知识注入与通用能力的平衡**：RS-EXPERT-BENCHMARK总分从73.35提升至87.60，而MMLU-Redux保持稳健（66.57→66.80），MATH-500和Multi-IF仅呈现轻微下降。
4. **每一步训练和架构组件都贡献增益**：Expert-tuning提升精确工具执行，VG-HRL进一步优化有序与精确执行；验证器对扁平智能体增益巨大（Exact从6.84/19.42→29.05/30.14），遥感专业化层次将Accuracy从30.24/33.47提升至43.95/45.56；移除验证导致Accuracy下降约4个百分点，证明层次专门化和步骤级验证是互补且不可或缺的。

### 7. 优点（亮点）

- **围绕领域工作流结构设计而非套用通用模板**：明确识别了现有系统的三个不匹配问题，提出的“管理层-专家层”架构与遥感的底层处理链同构，具有领域直觉性与设计针对性。
- **首次将层次化验证引导的强化学习系统性地引入遥感智能体**：管理层轨迹级和专家层步骤级的双层奖励设计，解决了长时程稀疏监督下的信用分配问题。
- **领域感知的验证机制的引入**：验证器不仅检查本地输出，还检索全局记忆进行物理/光谱/统计合理性检查。三步分级工具奖励（幻觉工具/错误工具/正确工具）为RL保存了更有信息量的组内方差，设计细致。
- **“知识注入→工作流对齐→策略优化”的三段式训练流水线**：模块清晰，每阶段可独立验证贡献。
- **实验结论有说服力**：在完全共享检查点的公平设置下证明了架构与训练方法的独立贡献；4B小模型能在特定指标上超过顶级闭源模型这一点令人印象深刻。
