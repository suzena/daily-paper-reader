## 摘要
地球观测（EO）智能体构建科学有效的工具工作流，并基于当前地理空间证据得出结论。这具有挑战性，因为EO工作流受传感语义、产品依赖、空间与时间兼容性以及参数要求的约束。现有智能体通常为每个查询在广阔的操作空间中搜索，而近期的自进化系统未能将异构的EO轨迹充分组织为跨不同决策级别的可复用知识。为解决这一问题，我们提出了GeoForge，一个免训练、自进化的框架，将已完成的轨迹转化为结构化的非参数执行状态。GeoForge根据传感上下文约束操作空间，然后从三个互补的记忆中检索任务条件化的先验。工作流图记忆捕获全局操作顺序，动作级经验提供局部修正，自适应技能标准操作程序保留过程和数据约束。检索到的先验指导工具执行，而当前观测仍是最终答案的基础。每个任务后，安全门控的蒸馏过程将基于事实的轨迹转化为可复用的执行知识，供未来检索。这种执行-蒸馏-复用循环在不更新骨干大语言模型（LLM）的情况下改进规划。在多个地理空间基准上的实验表明，GeoForge在多种LLM骨干上持续提高了任务准确性和工具使用轨迹质量，同时大幅减少了大多数LLM的工具规划和推理错误。

## Abstract
Earth observation (EO) agents construct scientifically valid tool workflows and ground their conclusions in current geospatial evidence. This is challenging because EO workflows are constrained by sensing semantics, product dependencies, spatial and temporal compatibility, and parameter requirements. Existing agents often search a broad operation space for each query, while recent self-evolving systems do not fully organize heterogeneous EO trajectories into reusable knowledge across different decision levels. To solve this problem, we present GeoForge, a training-free, self-evolving framework that transforms completed trajectories into a structured nonparametric execution state. GeoForge constrains the operation space according to the sensing context, then retrieves a task-conditioned prior from three complementary memories. Workflow Graph Memory captures global operation order, Action-Level Experiences provide local corrections, and the Adapted Skill Standard Operating Procedure preserves procedural and data constraints. The retrieved prior guides tool execution, while current observations remain the basis of the final answer. After each task, a safety-gated distillation process converts grounded trajectories into reusable execution knowledge for future retrieval. This execution, distillation, and reuse loop improves planning without updating the backbone LLM. Experiments on multiple geospatial benchmarks demonstrate that GeoForge consistently improves both task accuracy and tool-use trajectory quality across diverse LLM backbones, while substantially reducing tool-planning and reasoning errors for most LLMs.

## 2. 论文提出的方法论

### 2.1 核心思想

GeoForge将EO智能体视为一个持久化的认知系统：外部非参数记忆充当"程序性知识"的载体，在当前任务中检索相关先验来引导执行，同时用执行结果来持续更新记忆，形成自我进化闭环。

### 2.2 系统架构与关键组件

系统由三个层级的知识记忆组成，共同构建任务条件化的执行先验：

1. **工作流图记忆（Workflow Graph Memory）**
   - 有向、可靠性感知的图结构：节点为工作流，边为工具间转换关系；
   - 节点属性包括任务类型、工作流描述、压缩工具序列、参数提示、注意事项、来源和成功/失败计数；
   - 检索评分结合工具序列Jaccard相似度与文本语义相似度，并加入任务类型一致性奖励和过长序列惩罚：
     ```
     sG(q, wi) = α·Jtool(q, wi) + β·Jtext(q, wi) + λC·1[ci = ĉ(q)] − λL·max(0, |zi| − L0)
     ```

2. **动作级经验（Action-Level Experiences）**
   - 以"条件-修正"二元组存储细粒度的局部决策知识（如模态对齐、参数接地、空间不兼容处理等）；
   - 检索采用门控相关模型，结合词汇相似度与任务一致性约束，要求经验与查询有实际词汇重叠且必须来自可执行轨迹。

3. **自适应技能SOP（Adapted Skill SOP）**
   - 存储可复用的任务分解、中间产物、数据与参数约束、传感器语义和失败预防规则；
   - 通过LLM压缩算子 `AΘ` 将全局SOP适配为任务局部版本，兼顾高精度与高召回。

### 2.3 执行流程

推理阶段，GeoForge拼接检索到的图上下文、动作经验、适配SOP和确定性EO任务指引，构成紧凑执行上下文 `Cq`；随后在**过滤后的MCP工具空间**上执行标准ReAct过渡：

```
at ~ πΘ(·| q, Cq, ht, Tq)
```

记忆仅作为"处理先验"，最终答案始终以当前观测数据为基础。对于不完整回答，系统复用已有地理空间产物，仅调用缺失的操作，并通过确定性+LLM归一化器输出合法选项。

### 2.4 安全门控自进化

任务完成后，蒸馏器产生三类更新（最多3条经验、1份修订SOP、最多2个工作流候选），更新受安全门控函数 `ψ(τ, ŷ)` 约束，需要同时满足：
- 使用了工具（Tools > 0）√
- 回答不是不完整形式 √
- 调用次数不超过上限 √
- 单工具重复调用率在限制内 √
- 不包含禁止的代码类/非MCP模式 √

记忆更新方式因类型而异：图记忆采用归一化合并、按可靠性修剪；经验库只接受等价类之外的新条目；SOP仅在门控通过时以替换方式更新。

## 6. 论文的主要结论与发现

1. **任务准确率显著提升**：GeoForge在Earth-Bench的4/5骨干上取得最优准确率（如GPT-5上74.33%、DeepSeek-V3.1上77.09%），相对最强的Earth-Agent基线提升幅度达10~25个百分点；
2. **轨迹质量同步改善**：Tool-Any-Order、Tool-In-Order、Tool-Exact-Match在多数骨干上均有提升，表明工具选择更准确、执行顺序更合理；
3. **跨基准泛化良好**：ThinkGeo上Instruction Alignment达97.27%，GeoPlan-Bench上Recall key达1.00，均超越现有方法；
4. **三种记忆具有互补性**：消融显示，技能SOP对准确率贡献最大（去除后从74.33%降至52.66%），工作流图对轨迹质量贡献最大（去除后Tool-Any-Order从85.89%降至75.69%）；
5. **误差结构改善**：工具规划错误大幅减少，推理错误在多数骨干上被消除，剩余错误多为执行轨迹和参数层面的深层问题；
6. **超参数鲁棒**：Top-k=3、Min-Retrieve-Score=0.6为最佳配置，系统对该超参数变化不敏感。

## 7. 优点

- **免训练自进化范式新颖**：通过非参数记忆实现持续学习，规避了微调的高成本和灾难性遗忘问题，具有良好的可扩展性；
- **多级记忆体系设计精巧**：全局工作流图（顺序）、局部动作经验（修正）、任务SOP（过程约束）三者互补，覆盖了从宏观规划到微观执行的完整决策层级；

- **实验设计全面**：横跨多基准、多种骨干模型、多维度指标，包含消融、敏感性分析和错误归因，方法论验证较为扎实；

## 8. 不足与局限

- **算力成本未透明化**：虽免训练，但多次LLM推理调用+记忆蒸馏的开销未量化，"训练-free"不等同于"计算-free"；
- **异常结果缺乏解释**：GPT-4o骨干下Tool-In-Order指标意外大幅下降（53.20→37.31），论文未给出说明，可能暗示该方法与部分骨干存在兼容性问题；
- **对比公平性可改进**：部分基线缺少轨迹级指标，且未与更强的最新自进化EO系统（如GeoEvolve的完整配置）在同一指标集上对齐比较；
- **记忆增长的长期行为未探究**：随着经验积累，记忆是否会出现冗余、冲突、检索退化等问题，未见相关分析与应对策略；
- **场景覆盖有限**：主要面向光学/光谱遥感分析，对SAR、红外等多模态场景验证尚浅（仅提及TerraLogic相关工作），对海洋、气象等新兴EO领域未有涉及；
- **门控机制依赖先验规则**：安全门控的判定条件（如调用次数上限、重复率阈值）需要人为设定，不同场景下的最佳值可能差异很大，泛化性有待验证。
