## 摘要
对海洋滑翔机规划器进行重复的现场评估需要稀缺的航行器、操作人员、部署和回收资源，以及无法为竞争算法重置的海洋条件。我们提出了一个引导式的、无需安装的浏览器原生数字试验场，将选定区域转化为可复现的四维实验。该系统引导用户从区域选择出发，经过任务范围的水深、时间/深度强迫、科学目标、可选任务分解、路线规范、平流执行、观测生成和评分。其主要贡献是建立了一个通用的规划到观测契约，统一了手动路线、透明的内置算法以及导入的经典或学习型规划器输出中的航行器、感知和评估器假设，而导出的工件形成了数据集就绪的记录。一项受控的观测系统模拟实验（OSSE）评估了五个经典规划器，涉及两个场景、三个确定性种子和一个校准的60小时视界。所有54个任务均完成并回收，无硬性违规，而规划器排名和潜水策略效应揭示了运行与科学的权衡。一次真实的公开部署提供了现场参考审计，以界定当前运动学边界。另外，源代码锁定的GliderFlight 1.2.0通过Pyodide/WebAssembly实现了原生到浏览器的对等性，为高保真多层模拟建立了路径。最终运行空间在科学上可追溯，并在组件上符合任务规模部署前实验的要求。

## Abstract
Repeated in-situ evaluation of ocean-glider planners requires scarce vehicles, operators, deployment and recovery resources, and ocean conditions that cannot be reset for competing algorithms. We present a guided, installation-free browser-native digital test range that transforms a selected region into a reproducible four-dimensional experiment. The system leads users from regional domain selection through mission-scoped bathymetry, time/depth forcing, science objectives, optional task decomposition, route specification, current-advected execution, observation generation, and scoring. Its primary contribution is a common plan-to-observation contract unifying vehicle, sensing, and evaluator assumptions across manual routes, transparent built-in algorithms, and imported classical or learned-planner outputs, while exported artifacts form dataset-ready records. A controlled Observing System Simulation Experiment (OSSE) evaluates five classical planners in two episodes, three deterministic seeds, and a calibrated 60-hour horizon. All 54 missions completed and recovered without hard violations, while planner rankings and dive-policy effects revealed operational-scientific tradeoffs. An authentic public deployment supplied a field-referenced audit to scope current kinematic boundaries. Separately, source-locked GliderFlight 1.2.0 achieved native-to-browser parity through Pyodide/WebAssembly, establishing a pathway for high-fidelity multi-tier simulation. The resulting operational space is scientifically traceable and component-qualified for mission-scale pre-deployment experimentation.

- **核心问题**：海洋滑翔机规划算法的**现场评估成本高昂、资源稀缺且不可复现**。传统评估依赖实际部署的航行器、操作员、部署/回收资源，且海洋条件无法为不同竞争算法重置，导致方法间比较难以公平、透明地复现。

### 2. 方法论

#### 核心思想
建立一个**安装免安装（静态托管的浏览器原生）数字试验场**，将选定海洋区域转换为可复现的四维（经度、纬度、深度、时间）实验环境。其本质是一个端到端的“**规划到观测契约**”（plan-to-observation contract），将航行器、感知和评估器假设统一起来，使手动路线、内置算法、导入的经典/学习型规划器输出都能在同一框架下公平比较。

#### 关键流程（分阶段引导）
系统引导用户依次完成：**Bathymetry（水深）→ Currents（流场）→ Science（科学目标）→ Segments（任务分解）→ Routes（路线）→ Mission（任务规范）→ Simulate（模拟）→ Validate（验证/导出）**。

各阶段要点：

| 阶段 | 功能描述 |
|---|---|
| 水深 | 从 GEBCO_2026 15 弧秒网格提取任务范围水深；定义海洋/陆地/浅滩/禁行区掩码 |
| 流场 | 支持无流、受控解析生成器、冻结流场包、NetCDF/HDF5 导入或历史 HYCOM 子集；具有时间/深度支持 |
| 科学目标 | 定义隐藏参考场、规划器可见先验、不确定性、目标函数、采样价值与 QC |
| 分段 | 可选：定义区域、目标、走廊或多航行器责任分区 |
| 路线 | 手动航路点、内置基线（直航、Transect、A*系列）或导入外部规划器输出 |
| 任务 | 固定时钟、布放/回收、航行器速度、潜航策略、航路点接受半径、停留时间、间隙与观测调度 |
| 模拟 | 公共平流运动学推进；执行 4D 轨迹 (λ, ϕ, z, t) |
| 验证/导出 | 公共观测/QC、评估器、指标、构件与校验和 |

#### 关键技术细节

- **运动学模型**：航行器运动采用任务尺度流平流运动学：
  \[
  v_g(t) = v_w(t) + v_c(x(t), y(t), z(t), t)
  \]
  其中 \(v_g\) 为地速，\(v_w\) 为指令水中速度，\(v_c\) 为在已执行状态处采样的流场速度。施加航向/垂直速率限制、锯齿形潜航策略、航路点停留、掩码和间隙规则。

- **信息边界分离**（图1）：**规划器仅能访问允许字段**（水深、掩码、流场、先验、不确定性、采样价值）；**隐藏参考场对评估器独家可见**。显示/相机状态（视角、颜色、等高线、垂直夸大）不影响任何科学计算结果。

- **科学评分指标**：
  \[
  S_{rec} = 1 - \frac{RMSE_{post}}{RMSE_{prior}}
  \]
  先验仅控制产生 \(S_{rec}=0\)；所有方法使用相同调度、质量规则和评估器，观测重构采用距离加权局部核更新（以Barnes客观分析为方法论背景）。

- **多级模拟能力**：浏览器可执行 JavaScript 或 Web Worker/Pyodide 适配器中的模型；外部方法可输出相同规划构件。通过 Pyodide/WebAssembly 将 **GliderFlight 1.2.0** 源锁定飞行模型从原生 CPython 移植到浏览器并实现等价执行，为未来高保真多层级模拟奠定基础。

### 3. 实验设计

#### Benchmark / 场景
受控 OSSE（观测系统模拟实验），包含两个确定性子场景：
- **跨陆架锋（CSF）**：具有地理参考水深、掩码、3个时间层×深度层流场、隐藏标量参考场、先验、不确定性、采样价值。
- **深度剪切涡流（DSE）**：同上结构，但流场特征不同。

任务配置：单航行器、水中速度 0.42 m/s、30分钟步长、121个状态、**60小时视界**（经预检校准；原设计12小时不可行，预检发现布放-回收间距74.772 km，无流下界49.452小时）。采用固定潜航策略与加深潜航策略两种变体。

#### 对比方法（5种规划器）
1. **直航（Direct transit）**：仅布放与回收航路点。
2. **跨陆架横断面（Cross-shelf transect）**：3个种子依赖的中间航路点。
3. **水深 A***：测地代价 + 强浅水/逆深度惩罚。
4. **流场 A***：测地代价 + 逆流/横流惩罚（来自允许的平均流场）。
5. **科学 A***：测地代价 − 3500(V + 0.15σ)，其中 V 为规划器可见采样价值，σ 为先验不确定性；5个中间航路点 + 1800秒中点停留。

#### 数据与审计
- **受控基准**：两个场景 × 五种规划器 × 三个确定性种子 = **54 次排名运行**（固定漂移策略）。
- **固定/加深潜航策略对比**（额外的对比运行）。
- **真实现场审计**：部署于公共 IOOS Glider DAC 的历史数据集（`unit_308-20220826T2012`），含512,157条记录、1,746个剖面，最大深度193.75 m；因公共 DAC u/v 缺失而使用冻结 HYCOM GOMu0.04 流场；8个保留重放分段。
- **GliderFlight 对等测试**：原生 CPython 2次 vs 浏览器 Web Worker（Pyodide 0.26.4）2次。

### 6. 主要结论与发现

- **系统可行性**：54/54 次任务全部完成并回收、零硬违规，系统作为任务规模部署前实验环境可行。
- **规划器排名与指标依赖**：
  - CSF 中：直航距离最短，但水深感知 A* 和流场感知 A* 平均技能最高（0.966927）。
  - DSE 中：科学感知 A* 距离最短（87.701 km），但直航技能最高（0.966785）。
  - **最短方法不总是最高技能方法**——教学/操作上与“最短路径=最优”直觉形成对照。
- **潜航策略效应**：加深潜水政策增加最大采样深度 94 m、平均观测深度约 48.7–49.3 m、接受观测数 31–34 条，同时减少执行距离约 4.88–5.05 km；但技能变化很小（约 −2.5×10⁻⁴ 到 2.9×10⁻⁴），表明在近饱和评估器下潜航策略与技能存在微弱权衡。
- **浏览器-原生对等**：GliderFlight 1.2.0 在绝对容差 10⁻⁸、相对容差 10⁻⁷ 下八个输出字段确定性完全一致，零观测差异。
- **诚实限定**：现场回放准确度不足，说明精确现场轨迹复现需更高分辨率流场和更复杂的非线性航行器模型，指向未来多保真模拟方向。
- **适用边界**：当前引擎是任务尺度运动学，不是导航级或现场验证的非线性航行器模型；该系统适合任务级预部署实验与教育用途，而非导航/现场替代。

### 7. 方法/设计亮点（优点）

1. **无需安装、静态浏览器部署**：消除环境配置障碍，适配受管研究机与教室机器；Pyodide/WebAssembly 使科学计算完全在客户端完成。
2. **统一规划-观测契约 + 严格信息分离**：所有规划器看到相同允许字段、隐藏参考对评估器独家；显示层完全隔离于科学计算，保证“所见不影响所得”。
3. **端到端可追溯工作流**：从区域选择到评分全链路固化为冻结输入、规划、轨迹、观测、报告与校验和；形成数据集就绪记录，支持训练/评估数据集构建。
4. **多模式规划支持**：手动航路、透明基线算法、外部经典/学习型规划器共享同一接口，为未来 ML 规划器提供公平评估路径。
5. **多层级模拟路径**：运动学引擎用于快速迭代基准测试，GliderFlight 对等验证为高保真层级奠基。
6. **诚实方法论**：论文明确区分验证（已知答案测试）、校准（预检）、现场审计和基准推断的证据边界，不夸大显著性。

### 8. 不足与局限

1. **模型保真度有限**：当前引擎为任务尺度运动学，而非现场验证的非线性航行器动力学；真实回放端点复现未通过（8段中仅3段改善），说明与真实海洋存在偏差。
2. **OSSE 物理场理想化**：无噪声伪观测、平滑场、强先验，导致评估器技能接近饱和（0.965–0.967），区分度有限，难以捕捉规划器间细微差异。
3. **统计效力不足**：仅三个确定性种子，无法支撑显著性检验；排名结果应视为描述性而非推断性。
4. **学习型规划器缺失**：虽然接口支持，但本次未评估任何学习型/ML规划器，限制了契约泛化性的实证。
5. **现场审计数据局限**：公共 DAC 缺少 u/v 流数据，以 HYCOM 替代；端点误差较大（+1.16 km 中位变化），说明流场数据匹配精度不足。
6. **非导航级平台**：设计用于预部署实验与教育场景，不能直接用于实际导航/任务指挥。
7. **应用范围受限**：单航行器、有限任务时长、理想化观测调度；尚未覆盖多航行器协作、长时序部署等更复杂场景。
8. **部分图形界面夸大**：3D 地形垂直夸大 20× 等显示设置可能对非专家造成误解（虽不影响科学数据）。
