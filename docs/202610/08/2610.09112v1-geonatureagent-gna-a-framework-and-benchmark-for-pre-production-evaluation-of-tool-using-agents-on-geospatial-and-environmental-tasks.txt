## Abstract 

Before tool-using LLM agents are deployed in environmental and geospatial workflows, teams need evidence that an agent reliably selects the right operations against real APIs—yet no reusable, self-hostable substrate exists for such pre-production evaluation. We in-troduce GeoNatureAgent (GNA) , a framework for pre-production evaluation of tool-using agents. GNA publishes a fixed sixteen-tool geospatial interface (twelve principal operations and four auxiliary) as a Model Context Protocol (MCP) server, making the agent un-der test the only variable: any MCP-compatible client is a drop-in subject scored against an identical tool layer, task suite, and deter-ministic scorer. Its flagship instance is a 103-task benchmark—a 93-task main suite across 18 categories plus a ten-task compari-son expansion—spanning tool selection, multi-turn conversation, spatial reasoning, cross-indicator synthesis, error handling, multi-lingual understanding, and task rejection, among others, evaluated against an open, self-hostable geospatial API serving three envi-ronmental indicators across Spain and Portugal. We evaluate nine benchmark-tested large language models across Vertex AI, Open-Router, and Anthropic platforms under three temperature-1.0 seeds per model, reporting capability and per-case cost as orthogonal axes. Results manifest that: (1) Claude Sonnet 4 achieves the highest ca-pability at 61 .7% ± 0.7% on the combined 103 tasks (60 .8% ± 0.8% on the main suite), followed closely by DeepSeek V3.2 at 57 .9% ± 3.9%, while no other model exceeds 53%; (2) the cost-accuracy Pareto fron-tier is occupied mostly by open-weight models, with DeepSeek V3.2 offering 93% of Claude’s capability at 11.3 × lower list-price cost ($0 .011/case); and (3) under strict all-checks scoring, which requires

## 1 Introduction 

Environmental monitoring at scale requires multi-temporal geospa-tial analysis—detecting land cover change, assessing erosion risk, computing vegetation indices, and generating statistical summaries for regulatory compliance. Practitioners routinely spend most of their effort on data wrangling, discovering datasets, reprojecting coordinate systems, and debugging code against remote sensing APIs [18, 33]—an expertise barrier that limits adoption by domain scientists who understand environmental systems but lack GIS programming skills.

Recent advances in large language models (LLMs) have pro-duced agent systems that translate natural language into executable geospatial operations, from LLMs with tool pools [1, 33] to fine-tuned specialists [31, 32] to multi-agent systems achieving 85– 97% accuracy [17, 19], with heavy industry investment behind them [11, 23, 27]. However, a critical evaluation gap persists: the few public geospa-tial agent benchmarks target general GIS tasks (GeoBenchX [15], ThinkGeo [24]) rather than environmental science workflows; knowledge benchmarks (EnviroExam [12]) evaluate knowledge, not agent behavior; code-generation benchmarks (UnivEARTH [13]) do not reflect the structured API interaction production systems employ —58% of LLM-generated Earth Engine code fails to execute; and GEO-Bench/GEO-Bench-2 [16, 25] evaluate pixel-level vision models, not agent-level tool orchestration. We fill this gap with GeoNatureAgent (GNA) , a framework that reframes agent evaluation as connecting an agent to a fixed, standards-based tool substrate and scoring its behavior determinis-tically. GNA contributes: (1) A reusable agent-evaluation substrate —a fixed sixteen-tool geospatial interface published as a Model Context Proto-col (MCP) server, paired with a 103-task benchmark (93-task main suite across 18 categories + ten-task expansion) and a deterministic eight-check scorer (no LLM-as-judge). With tools, tasks, and scorer fixed, any MCP-capable agent is a drop-in subject-under-test—a reusable substrate, not a one-off harness. (2) Multi-seed cross-platform evaluation —a systematic comparison of nine LLMs spanning closed-source models and open-weight families, each evaluated under three temperature-1.0 seeds on identical infrastructure with mean-±-standard-deviation reporting; capability and per-case cost are reported as orthogonal axes rather than collapsed into a single gated score. (3) Cost-efficiency Pareto analysis —a quantitative mapping showing the Pareto frontier is mostly open-weight, with DeepSeek V3.2 offering 93% of Claude’s capability at 11.3 ×

lower list-price cost. (4) Reproducible MLOps pipeline and open API —a fully automated Cloud Build pipeline producing conversation-trace-level results, plus an Apache-2.0 self-hostable FastAPI service so the entire evaluation can be reproduced without any private endpoint. Throughout the results, a Build your own note closes each subsec-tion, naming the committed code path that reproduces the analysis and scales it to new models, tasks, indicators, and regions. 

Relation to prior publication. This paper substantially extends our SIGSPATIAL 2026 poster [9], which introduced the benchmark. New beyond that four-page prior publication are: the framework-first formulation and the MCP tool substrate (Section 3), the nine-model leaderboard (adding GPT-4o and Gemma-3-27B), the v6 close-value expansion (Section 6.5), the universal tool-call parser, and the expanded failure taxonomy and cross-benchmark positioning; all empirical results herein are new or re-derived. 

## 2 Related Work and Positioning 2.1 Geospatial AI Agent Architectures 

The literature reveals four paradigms of geospatial AI agent architectures. The LLM + Tool Pool approach pairs general-purpose LLMs with callable tools (GeoGPT [33], LLM-Geo [18], GIS Copilot [1]). Fine-tuned specialists sacrifice generality for expertise: GTChain [31] achieved 32 .5% higher accuracy than GPT-4; EnvGPT [32] fine-tuned an 8B model on 100M environmental tokens, rivaling GPT-4o-mini. Multi-agent systems decompose tasks: GeoJSON Agents [19] achieved 97% with a GPT-4o Planner-Worker architecture vs. 49% single-agent; GeoLLM-Squad [17] gained 17% from specialized sub-agents. 

Cost-efficient hybrids : Geo-OLM [26] enables sub-7B models to perform within 10% of GPT-4o at 100 × lower cost. 

## 2.2 Benchmarks and Evaluation 

Agent tool-use is evaluated by GeoBenchX [15], ThinkGeo [24] (486 remote sensing tasks), and UnivEARTH [13] (only 33% ac-curacy on Earth Engine code generation and a 58% code failure rate). GeoBenchX is the closest comparable work: 202 tasks across five categories, evaluated via 24 general-purpose GIS tools with an LLM-as-judge protocol; crucially, its tools are low-level prim-itives operating on local files ( load_data , filter_categorical ,

make_choropleth_map ), whereas GNA tools are high-level domain operations against a production cloud API (Table 1). Map reasoning: MapEval [10] (no model exceeds 67%), MapQA [3] (humans 91%, models < 50%). Spatial reasoning: GPSBench [28], SpatiaLab [29] (humans 88%, best model 55%). Foundation models: GEO-Bench [16] and GEO-Bench-2 [25] evaluate pixel-level classification/segmentation ( can this model classify a satellite tile? ), complementary to GNA’s agent-level tool orchestration ( can this agent reason about which tools to call? ); PANGAEA [20] finds that foundation models do not consistently outperform supervised baselines. 

## 2.3 Environmental Science AI 

Specialized models such as EnvGPT [32] demonstrate that focused fine-tuning on environmental tokens allows smaller architectures to rival general-purpose models like GPT-4o-mini. In industry, Google’s Earth AI [11] reaches 82% accuracy on geospatial Q&A (vs 50% baseline Gemini), and MCP-grounded interfaces reach a factual precision of 4 .78 /5.0 in air quality monitoring [22]. Regu-latory mandates such as Spain’s RD 214/2025 [14], which requires roughly 4 , 000 organizations to report carbon footprints, further drive demand for automated geospatial analysis. 

## 2.4 Positioning 

No existing benchmark evaluates environmental analysis agents performing structured tool calling against a real geospatial API with multi-turn conversation, multilingual inputs, and cross-indicator synthesis. GNA fills this gap; this paper extends our prior bench-mark [9] with the framework formulation, the MCP tool substrate, and the expanded empirical study enumerated in Section 1. GNA’s best-model accuracy (60 .8%, Section 6) is notably lower than the 85–97% reported by GeoBenchX and GeoJSON Agents. Four fac-tors may contribute: (1) real API interaction vs. local file operations; (2) environmental domain complexity (geographic knowledge, data limitations, display-only layers); (3) multi-turn conversation his-tory; and (4) strict binary evaluation. Only the last can be tested with our own data, and it explains much of the gap: under par-tial credit (fraction of checks passed) the top four models reach 86–90%, comparable to the range reported elsewhere, although the comparison still controls for neither task sampling nor rubric. The strict gap therefore measures end-to-end task completion, which deployment requires, rather than per-step competence; we read the cross-benchmark comparison as indicative, and a same-protocol re-run of prior suites is future work (Section 8). Our accuracies align with the harder map- and spatial-reasoning benchmarks above. Against code generation, structured tool calling constrains the out-put space: our 60 .8% on real API tool calls compares favorably with UnivEARTH’s 33% and 58% code-execution failure rate [13], again across protocols but consistent with structured APIs being the safer choice over free-form code generation for production environmen-tal systems.

## 3 The GNA Framework 

The benchmark as an MCP tool server. To make GNA a reusable 

substrate rather than a one-off harness, we expose its sixteen-tool interface as a Model Context Protocol (MCP) server [2], an open standard for connecting language-model agents to external tools. The server is a thin wrapper ( ∼95 lines) over the same tool defini-tions and dispatcher used by the evaluation harness and the pro-duction API—no tool logic is reimplemented—so any MCP-capable client (Claude Desktop, an OpenAI-style agent, or our own evalua-tion loop) drives an identical tool layer, byte-for-byte the one the API serves. This cleanly separates the benchmark (the fixed tools, data, and scorer) from the agent under test (the only variable): an evaluation is simply to connect an agent to the MCP server, issue the task prompts, and score the resulting tool calls deterministically. 

A deliberately tools-only surface. MCP defines several server capabilities— Tools (discover and invoke callable operations), Re-sources (server-supplied readable data/context), and Prompts (server-supplied templates/scaffolding). GNA implements only the Tools capability (list_tools and call_tool ). This is central to what the benchmark measures: the competency under evaluation is tool selection —whether an agent chooses the right tool, with the right ar-guments, at the right time, from natural-language intent. Exposing 

Resources would let an agent read pre-baked context and bypass the tool-choice decision; exposing Prompts would hand it scaffolding that leaks the solution path—either would contaminate precisely the capability we score. The in-process harness and the MCP trans-port present an identical decision surface, so results are comparable across both. Figure 1 shows the system architecture. The agent operates in a ReAct-style loop [30]: it receives a query, reasons about tools, executes calls, observes results, and generates a response. The agent has access to sixteen tools: the twelve principal operations in Table 2, plus four auxiliary tools for layer discovery and erosion time-series statistics. 

Figure 1: GNA system architecture. The LLM agent interacts with a production API serving COG data; the eval harness logs all tool calls and scores responses. NL denotes natural language. 

Multi-backend inference client. Fair cross-model comparison re-quires normalizing heterogeneous API surfaces: a native Anthropic backend and a LiteLLM backend for OpenAI-compatible endpoints normalize responses —including tool-call representations —into the one schema the eval harness consumes. Notably, Llama 4 models emit tool calls as Python-style function invocations rather than JSON; a dedicated AST-based parser extracts these so Llama 4 Scout is scored on the same footing as the JSON-native models. 

Build your own: the substrate is domain-agnostic—replacing the tool executors behind the MCP server ( api/agent/mcp_server. py ) with your own domain’s operations and the task JSON with your own cases yields a benchmark for that domain, with dispatcher, ReAct loop, scorer, and aggregation unchanged. ## 4 The Benchmark Instance 

GeoNatureAgent Benchmark comprises 103 tasks: a 93-task main suite organized into 18 categories (see Table 3), spanning easy (19%), medium (47%), and hard (33%) difficulty levels, plus the ten-task v6 expansion (Section 6.5), reported both separately and in a combined 103-task metric. Each task specifies: a natural language query (optionally with multi-turn history), expected tool calls, must-contain/must-not-contain strings, maximum rounds, cost budget, and domain-expert ground truth. Error handling tasks are deliberately unsolvable (non-existent municipalities, statistics requested from display-only lay-ers), testing the agent’s ability to decline gracefully rather than hallucinate. 

Worked example. Consider case V5_21 (comparison): “Compare CO 2 geological storage suitability between Murcia and Córdoba. Which province is better suited?” The gold solution issues a single 

compare_areas call, which returns Murcia 68 .5% vs. Córdoba 68 .4%—within tolerance ( Δ0.1 pp against 2 .0 pp), i.e. effectively tied. Every model fails this case: most runs never issue the comparison call (a tool-missing error), and the few that do still miss on answer phrasing, not on the 0 .1-point margin—a failure of tool selection ,not numeric discrimination. The benchmark covers three environmental indicators across two countries: 

• CO 2 absorption suitability (categorical, Spain): legislative pre-screening encoding five MITECO spatial criteria [14], producing three classes (Not Eligible, Eligible with Condi-tions, Eligible). Served as a Cloud Optimized GeoTIFF (COG). 

• Gully erosion probability (continuous, Europe): machine learning prediction from the LUCAS 2022 soil survey [5] (0–100%). Served as a COG. 

• BigEarthNet V2 land cover (categorical, Portugal): 7-class land cover distribution derived from 75k+ labeled Sentinel-2 patches [6], aggregated by Portuguese district. Served as pre-computed JSON statistics.

Seven additional layers are available for visual display but not for statistical analysis, creating natural hallucination traps. To align our tool surface with general-purpose GIS benchmarks, we integrate four canonical GIS operations from GeoBenchX [15] into our toolset: proximity buffering ( create_buffer ), feature se-lection by spatial relationship ( select_features_by_spatial_ relationship ), centroid extraction ( get_centroids ), and explicit task rejection ( reject_task ) to prevent hallucination on out-of-scope queries. These are adapted from GeoBenchX’s local-file para-digm to operate against the cloud API, are available across the full 103-case suite, and are invoked wherever a query calls for a spatial operation rather than through dedicated cases. 

Design rationale. The category structure is a capability taxon-omy: each category isolates one agentic competency required for environmental geospatial analysis. Case counts are weighted by capability importance rather than balanced—tool selection receives the most cases (21) because it is the pivotal agentic skill (Section 6.6), whereas niche capabilities receive one or two. The uneven sizes are deliberate; we treat the aggregate leaderboard as the primary mea-sure and category-level results as indicative (Section 6). Difficulty labels are author-assigned by expected tool-chain depth and are approximate. 

Tool coverage across data domains. Tool coverage varies by layer: the CO 2 and gully-erosion indicators (raster COGs, Spain/Europe) GeoNatureAgent (GNA) GeoIndustry ’26, November 03–06, 2026, Riverside, CA, USA

## 5 Evaluation Protocol 

Each task is scored by eight check types (see Table 4). A task passes 

only when all applicable capability checks pass (strict binary; the cost budget is reported, not gated). We additionally compute partial-credit metrics for finer-grained analysis.

Continuous metrics. Beyond binary pass/fail, we report check score (fraction of checks passed per case), keyword coverage , tool F1 , and cost utilisation . Tool and action checks gate on recall rather than F1: an agent that calls all expected tools plus an exploratory extra should not be penalised. 

Error classification. When a task fails, the first failing check (in priority order: tool_missing → chart_missing → wrong_data 

→ rounds_exceeded → cost_exceeded → keyword_missing →

forbidden_keyword ) determines the error category; runs that fail only on cost_exceeded are excused by the capability metric, so the distribution (Table 8) reports the dominant failure mode per run, not an exhaustive multi-label tally. 

Capability and cost as orthogonal axes. Per-case cost budgets are deployment thresholds, not measures of reasoning ability, so we decouple them: the binary leaderboard scores capability only, and per-case cost is a Pareto axis (Section 6.3), following HELM [4] and GAIA [21]. Cost-gated numbers remain recoverable from the per-case CSV ( passed_with_cost_gate ). 

## 6 Experiments and Results 6.1 Experimental Setup 

We evaluate nine LLMs on the full 103-task GeoNatureAgent Bench-mark (93-task v5 main suite, 18 categories, plus the ten-task v6 expansion; Section 6.5) across Vertex AI Model-as-a-Service, Open-Router, and the Anthropic Messages API (see Table 5). All experi-ments use the v3 system prompt (a zero-shot ReAct-style instruc-tion, committed at api/agent/prompts/v3.md ), max_turns=10 ,

max_tokens=4096 , and temperature=1.0 —chosen to expose run-to-run variance under realistic sampling noise rather than the deter-ministic temperature-0 regime that overstates production stability. The prompt is held constant across all models to isolate capability from prompt-engineering effort, and experiments run sequentially inside a single Cloud Run Job to ensure identical infrastructure conditions.

Build your own: adding a model to this leaderboard is one experiment YAML in benchmark/experiments/ pointing at any OpenAI-compatible or Anthropic endpoint; the committed aggregation scripts re-emit the leaderboard and per-category CSVs, and scripts/scaling_stats.py recomputes the scale trend as the open-weight sample grows. 

Partial credit tells a different story. Per-check partial credit is far higher than strict accuracy: 71–90% across the nine models and 86– 90% for the top four. Failing cases often show partial competence— correct tools but a missing keyword—so many failures are “near-misses”, and this scoring difference is the main measurable reason our strict accuracies sit below those of looser-scored benchmarks (Section 2.4). 

Bootstrap confidence intervals. To quantify how much of the inter-model spread is small-sample noise, we compute 95% bootstrap confidence intervals on the accuracy of each of the seven original v5 models by resampling the 93 main-suite cases (2 ,000 resam-ples). The intervals are wide and overlap substantially between adjacent models—Claude Sonnet 4 [51 .1, 69 .9] and DeepSeek V3.2 

[47 .7, 64 .5] overlap almost entirely, as do GLM-5 [41 .2, 58 .1] and Gemini 2.5 Pro [39 .8, 56 .3]—so adjacent-model and category-level rank claims should be read as indicative rather than definitive at 𝑛 = 93. Only the top-versus-bottom gap sits well outside any overlap: Llama 4 Scout’s interval [19 .7, 33 .7] lies entirely below Claude Sonnet 4’s [51 .1, 69 .9].

6.4.1 Hard and Model-Dependent Categories. Several small cate-gories are hard or strongly model-dependent (Figure 4; most hold two to four tasks, so these are indicative):

The close-value finding above rests on a single case ( V5_21 ), so we ran a ten-task expansion set ( v6 ) of comparison-heavy queries over GeoIndustry ’26, November 03–06, 2026, Riverside, CA, USA Diaz-Ireland et al. 

the Portuguese BigEarthNet land-cover layer, spanning ground-truth value gaps from 0 .6 to 45 .1 percentage points. It includes a deliberate large-gap control ( V6_05 , 45 .1 pp), two legend-reading tasks, and three aggregation tasks (a threshold count, a sum, and a sum-then-compare). All nine leaderboard models were run under the identical three-seed, temperature-1 .0 protocol (Table 9). Three findings refine the v5 result. First, the “unsolved by ev-ery model” statement is not universal : under strict (raw) scoring Gemini 2.5 Pro solves the majority of comparison runs (67%, in-cluding the control at 100%) and GPT-4o reaches 50%, so at least two models can discriminate near-equal values. Second, difficulty does not track the value gap (Figure 3, left): pooled raw accuracy is essentially flat across gaps (26% at 0 .6 pp, 37% at 1 .2 pp, 19% at 2.1 pp; one task per gap, so indicative), the large-gap control is no easier (22% raw), and the sum-then-compare task ( V6_10 ) is the hardest of all (0% raw across every model and seed). The deficit is therefore not near-equal numeric discrimination but the multi-step tool composition the Portugal layer demands (served only by 

analyze_area , each comparison requires several sequential calls). Third, this manifests as a raw-versus-capability gap (Figure 3, right): capability scoring—which excuses budget/round exhaustion, whereas the v5 leaderboard excuses cost only—lifts comparison accuracy to 67–83% for the top models, so most comparison “fail-ures” are timeouts mid-composition rather than wrong answers; Claude Sonnet 4 is the extreme case at 83% comparison capability but 0 /18 raw. The expansion thus treats the v5 close-value case as indicative rather than a fundamental limitation, re-attributing the residual difficulty to tool composition and turn budget (Figure 3).

## 6.7 Prompt-version sensitivity and reproducibility 

Two controls govern how any tool-calling leaderboard should be read: how much the system prompt moves scores, and whether the harness reproduces. Re-running the v5 suite under the paper’s v3 prompt on three current models (single seed) probes both. Moving from the runner’s default (v2) prompt to v3 raises Claude Haiku 4.5 by +22 .6 pp (25 .8% → 48 .4%) and Gemini 2.5 Pro by +11 .8 pp (30 .1% → 41 .9%)—a swing larger than every adjacent-rank gap in Table 6, which is why the v3 prompt is held fixed across all models. The fresh Gemini 2.5 Pro run (41 .9%) falls inside the paper’s three-seed 95% bootstrap interval ( [39 .8, 56 .3], mean 48 .0%), confirming the harness reproduces to within sampling noise; Claude Sonnet 4.5 scores 30 .1% despite an 85% partial-credit score—a tool-call format mismatch under our scorer (flagged for verification), not reduced capability. These rows are reported alongside, not as a re-ranking of, the accepted nine-model leaderboard. ## 8 Limitations and Future Work 

Limitations. Small samples : with 93 main-suite tasks across 18 categories, roughly half hold three or fewer instances, so category-and failure-mode claims are indicative; the aggregate leaderboard is better powered than any single category. Serving heterogene-ity : provider-managed stacks with uncontrolled quantization and region (Table 5) confound absolute latency and cost, though not the shared tool interface. Single-region data : indicators cover only Spain and Portugal, so geographic generalization is untested. Eval-uation strictness : binary pass/fail understates per-step capability (partial credit 71–90%) and accounts for much of the gap versus looser-scored benchmarks (Section 2.4); no prior suite has yet been re-run under our protocol. Architecture scope : every system is a single-agent ReAct loop; multi-agent decompositions deliver large gains on adjacent benchmarks [17, 19]. 

Future work. Extensions follow directly. Scoring : tolerance-/range-based scoring so near-equal comparisons survive strict binary matching, plus a pass 𝑘 reliability metric for production consistency, and re-running prior suites (e.g., GeoBenchX) under GNA’s protocol for a same-protocol comparison. Coverage : ex-panding the model roster, thin categories, task types, regions, and indicators would raise power and test generalization. Substrate :exposing the other MCP primitives (resources, prompts) and subagent-orchestrated clients would broaden the constructs under test. Sustainability : refining the energy/carbon estimate toward measured per-token footprints would make footprint a first-class metric. 

## 9 Conclusion 

We introduce GeoNatureAgent (GNA), a framework for pre-production evaluation of tool-using agents whose flagship instance benchmarks environmental geospatial analysis through structured tool calling against an open, self-hostable API. Evaluating nine LLMs on 103 tasks (93-task main suite + ten-task expansion) under three temperature-1.0 seeds: (1) End-to-end tool orchestration on our environmental suite remains open. The capability leader (Claude Sonnet 4) achieves 60 .8% ±0.8% on the main suite under strict all-checks scoring (capability-scored 61 .7% ± 0.7% on all 103 tasks); only two models exceed 55% and none reaches 65%. Per-check partial credit is far higher (86–90% for the top four), so much of the gap to the 85–97% reported on general GIS benchmarks GeoIndustry ’26, November 03–06, 2026, Riverside, CA, USA Diaz-Ireland et al. 

reflects our stricter, completion-based scoring (indicative; not a same-protocol comparison). (2) Open-weight models occupy the cost-accuracy Pareto frontier. Three of the four frontier models are open-weight (Llama 4 Scout, Qwen3-235B, DeepSeek V3.2). (3) The capability-cost trade-off is steep. DeepSeek V3.2 delivers 93% of Claude’s capability (56 .3% vs. 60 .8%) at 11 .3×

lower per-case list-price cost. (4) Systematic failures persist. Missing tool calls dominate failures (68%), and parameter scale tracks capability only within our small open-weight sample. GNA is offered as a recipe as much as a result: swap the tool ex-ecutors behind the MCP server for your domain’s operations, write task JSON, and the committed pipeline produces the leaderboard, Pareto frontier, failure taxonomy, and category breakdown for your 

domain. GNA—the MCP tool server, evaluation harness, bench-mark, and self-hostable API—is publicly available at https://github. com/gabrielireland/GeoNatureAgent_Benchmark; the dataset and software are archived at Zenodo [7, 8].
