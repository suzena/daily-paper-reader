## 摘要
在将使用工具的 LLM 智能体部署到环境与地理空间工作流之前，团队需要证据表明智能体能够针对真实 API 可靠地选择正确操作。我们提出 GeoNatureAgent (GNA)，一个用于工具使用型智能体生产前评估的框架：一个固定的十六工具地理空间接口，以 Model Context Protocol (MCP) 服务器形式发布，因此被测智能体是唯一变量，并针对相同的工具层、任务套件和确定性评分器进行评分。其旗舰实例是一个 103 任务基准（包含覆盖 18 个类别的 93 任务主套件，以及一个十任务对比扩展），针对一个开放、可自托管的地理空间 API 进行评估，该 API 在西班牙和葡萄牙提供三项环境指标。我们在三个温度为 1.0 的随机种子下评估九个 LLM，将能力和单案例成本报告为正交轴。(1) Claude Sonnet 4 取得最高能力（全部 103 个任务上为 61.7% +/- 0.7%；主套件上为 60.8%），紧随其后的是 DeepSeek V3.2（57.9%），而其他模型均未超过 53%；(2) 成本-准确率帕累托前沿主要由开放权重模型占据，DeepSeek V3.2 以低 11.3 倍的标价成本提供 Claude 93% 的能力；(3) 在严格的全检查评分下，最佳模型比通用 GIS 基准上报告的 85-97% 低 24-36 个百分点，而前四名模型的逐检查部分得分（86-90%）与之相当，因此该差距的很大一部分反映的是评分严格性，而不只是任务难度。MCP 服务器、评估工具链、基准和 API 均已公开可用；替换工具执行器和任务套件即可为任意地理空间领域实例化一个等效基准。

## Abstract
Before tool-using LLM agents are deployed in environmental and geospatial workflows, teams need evidence that an agent reliably selects the right operations against real APIs. We introduce GeoNatureAgent (GNA), a framework for pre-production evaluation of tool-using agents: a fixed sixteen-tool geospatial interface published as a Model Context Protocol (MCP) server, so the agent under test is the only variable, scored against an identical tool layer, task suite, and deterministic scorer. Its flagship instance is a 103-task benchmark (a 93-task main suite across 18 categories plus a ten-task comparison expansion) evaluated against an open, self-hostable geospatial API serving three environmental indicators across Spain and Portugal. We evaluate nine LLMs under three temperature-1.0 seeds, reporting capability and per-case cost as orthogonal axes. (1) Claude Sonnet 4 achieves the highest capability (61.7% +/- 0.7% on all 103 tasks; 60.8% on the main suite), followed closely by DeepSeek V3.2 (57.9%), while no other model exceeds 53%; (2) the cost-accuracy Pareto frontier is mostly open-weight, with DeepSeek V3.2 offering 93% of Claude's capability at 11.3x lower list-price cost; (3) under strict all-checks scoring the best model sits 24-36 points below the 85-97% reported on general-purpose GIS benchmarks, whereas per-check partial credit for the top four models (86-90%) is comparable, so much of that gap reflects scoring strictness rather than task difficulty alone. The MCP server, evaluation harness, benchmark, and API are publicly available; swapping the tool executors and task suite instantiates an equivalent benchmark for any geospatial domain.

## 1. 核心问题与整体含义

- **研究动机**：环境监测规模化依赖多时相地理空间分析（土地覆盖变化、侵蚀风险评估、植被指数计算、法规合规统计等），但从业者大量精力消耗在数据整理、数据集发现、坐标重投影与 API 调试上，形成专业知识壁垒，限制了懂环境系统但缺乏 GIS 编程能力的领域科学家采用。
- **技术背景**：LLM 智能体已能将自然语言转化为可执行地理空间操作（工具池、微调专家、多智能体系统），工业界投入巨大（Google Earth AI 达 82% 地理问答准确率）。
- **评估缺口**：
  - 现有公开地理空间智能体基准（GeoBenchX、ThinkGeo）面向通用 GIS 任务，而非环境科学工作流。
  - 知识基准（EnviroExam）评估知识而非智能体行为。
  - 代码生成基准（UnivEARTH）不反映生产系统采用的结构化 API 交互，且 58% 的 LLM 生成 Earth Engine 代码无法执行。
  - GEO-Bench/GEO-Bench-2 评估像素级视觉模型，而非智能体级工具编排。
- **整体含义**：GNA 将智能体评估重构为“将智能体连接到固定的、基于标准的工具基底，并确定性地对其行为评分”，填补了环境分析智能体在真实地理空间 API 上进行结构化工具调用评估的空白。

## 2. 方法论

### 核心思想
- 将基准做成 **MCP（Model Context Protocol）工具服务器**：固定十六工具地理空间接口（12 个主要操作 + 4 个辅助工具），使被测智能体成为唯一变量。任何 MCP 兼容客户端都是即插即用的受试对象，针对相同工具层、任务套件和确定性评分器评分。
- **刻意仅暴露 Tools 能力**：不暴露 Resources（预烘焙上下文会绕过工具选择决策）和 Prompts（会泄漏解题路径），以保证评估的正是“工具选择”这一核心能力。

### 关键技术细节
- **系统架构**：智能体运行 ReAct 风格循环（接收查询 → 推理工具 → 执行调用 → 观察结果 → 生成响应）。
- **工具集**：
  - 领域专用 8 个：`lookup_province`、`lookup_municipality`、`analyze_area`、`analyze_multi_layer`、`compare_areas`、`find_top_n`、`toggle_layer`、`generate_chart`。
  - 改编自 GeoBenchX 的 4 个：`create_buffer`、`select_spatial_rel`、`get_centroids`、`reject_task`。
  - 4 个辅助工具：图层发现与侵蚀时间序列统计。
- **多后端推理客户端**：原生 Anthropic 后端 + LiteLLM 后端（兼容 OpenAI 端点），统一响应与工具调用表示为单一 schema。针对 Llama 4 的 Python 风格函数调用，使用基于 AST 的解析器。
- **评分器（八类检查）**：`expected_tools`（召回=1.0）、`expected_actions`、`must_contain`、`must_not_contain`、`numeric_accuracy`（标签后 120 字符窗口内首个百分比，默认 ±2pp 容差）、`chart_generated`、`max_rounds`、`max_cost_usd`（仅报告不门控）。
- **严格二值通过**：所有适用能力检查通过才判定任务通过；额外工具调用不惩罚（工具/动作检查基于召回而非 F1）。
- **连续指标**：check score、keyword coverage、tool F1、cost utilisation。
- **错误分类优先级**：`tool_missing → chart_missing → wrong_data → rounds_exceeded → cost_exceeded → keyword_missing → forbidden_keyword`。
- **能力与成本正交**：遵循 HELM 与 GAIA，二值排行榜仅评能力，单例成本作为帕累托轴。

## 3. 实验设计

### 数据集 / 场景
- **三个环境指标，覆盖两国**：
  - **CO₂ 吸收适宜性**（分类，西班牙）：编码五项 MITECO 空间标准的立法预筛选，三类别，以 COG 提供。
  - **沟蚀概率**（连续，欧洲）：基于 LUCAS 2022 土壤调查的 ML 预测（0–100%），以 COG 提供。
  - **BigEarthNet V2 土地覆盖**（分类，葡萄牙）：75k+ 标注 Sentinel-2 图块聚合为 7 类分布，按葡萄牙区级统计，以预计算 JSON 提供。
- 另有 7 个仅可视化、不可统计分析的图层，构成自然幻觉陷阱。

### Benchmark 构成
- **103 任务**：93 任务主套件（18 类）+ 10 任务 v6 对比扩展。
- **18 类**：工具选择 21、跨指标 8、深度剖析 6、解释 7、错误处理 6、栖息地分析 7、语言 6、市政 4、记忆（多轮）6、空间推理 4、多市政排名 3、阈值 3、时间变化 1、错误恢复 3、排名 2、比较 2、单分析 2、省份聚合 2。
- **难度分布**：易 19%、中 47%、难 33%。
- **错误处理任务刻意不可解**（不存在市政、显示专用图层请求统计），测试优雅拒绝能力。
- **v6 扩展**：10 个对比密集型任务，值差距 0.6–45.1pp，含大差距对照、两个图例阅读、三个聚合任务。

### 对比方法 / 模型
- **九个 LLM**：DeepSeek V3.2（671B MoE）、GLM-5、Gemini 2.5 Pro、Claude Sonnet 4、GPT-4o、Qwen3-235B（235B MoE）、GPT-OSS-120B、Llama 4 Scout（109B MoE）、Gemma-3-27B。

- **协议**：`max_turns=10`、`max_tokens=4096`、`temperature=1.0`、v3 系统提示（零样本 ReAct），每模型三个种子 `{42, 1337, 2024}`（Claude 因 API 不支持种子，用两个独立温度-1.0 样本）。
- **跨基准定位**：与 GeoBenchX（202 任务、24 低层原语、LLM-as-judge、本地文件）进行非同协议对比。

## 6. 主要结论与发现

1. **端到端工具编排仍是开放挑战**：Claude Sonnet 4 最高，103 任务 61.7%±0.7%，主套件 60.8%±0.8%；DeepSeek V3.2 第二（57.9%±3.9%）；仅两个模型超 55%，无一达 65%。
2. **部分信用远高于严格准确率**：九模型 71–90%，前四名 86–90%，说明许多失败是“差一点”（工具对但关键词缺失），严格全检评分是 GNA 低于通用 GIS 基准 85–97% 的主要可测原因。
3. **成本-准确率帕累托前沿多为开放权重**：前沿由 Llama 4 Scout、Qwen3-235B、DeepSeek V3.2、Claude Sonnet 4 占据，其中 3/4 为开放权重。
4. **成本-能力权衡陡峭**：DeepSeek V3.2 以 Claude 93% 的能力（56.3% vs 60.8%）实现 11.3× 更低的单例标价成本（$0.011 vs $0.127）；按 1000 查询/天外推，Claude $127/天 vs DeepSeek $11.3/天。
5. **失败集中在工具选择而非数据处理**：68.0% 失败为 tool_missing，19.3% keyword_missing，9.7% wrong_data。
6. **规模趋势**：在 5 个披露参数量的开放权重模型（27B–671B）中，准确率随参数量单调上升（Spearman ρ=1.0，Pearson r=0.98 on log params，置换检验 p=0.017）。
7. **v6 扩展修正 v5 结论**：难度不随值差距变化，大差距对照并不更容易；残差困难归因于工具组合与轮次预算，而非近似数值判别；能力评分下比较任务可达 67–83%。
8. **碳足迹由 token 驱动**：token 密集的 DeepSeek V3.2 单例碳排（6.42 gCO₂）几乎与 Claude（6.44 gCO₂）持平，尽管美元成本低 11.3×，解耦了碳与成本轴。
9. **提示版本敏感**：从 v2 到 v3 提示，Claude Haiku 4.5 提升 +22.6pp，Gemini 2.5 Pro 提升 +11.8pp，摆动大于所有相邻排名差距。

## 7. 优点

- **框架可复用、领域无关**：MCP 标准工具基底，替换工具执行器与任务 JSON 即可实例化为任意地理空间领域基准，dispatcher、ReAct 循环、评分器、聚合逻辑不变。
- **实验控制严谨**：工具层、任务套件、评分器固定，被测智能体是唯一变量；提示版本化并跨模型固定；单 Cloud Run Job 保证基础设施一致。
- **确定性评分**：无 LLM-as-judge，八类检查二值门控，结果可复现、可审计。
- **能力与成本正交报告**：遵循 HELM/GAIA，避免将部署阈值与推理能力混为一谈。
- **多维度分析丰富**：部分信用、bootstrap CI、失败分类、类别热图、成本-碳足迹、提示敏感性、跨数据集扩展。
- **工程实现完善**：多后端推理客户端、
