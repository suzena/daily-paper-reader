Abstract — Aerial vision-and-language navigation (VLN) en-ables unmanned aerial vehicles to execute long-horizon natural-language instructions from visual observations in complex three-dimensional environments. However, recent aerial VLN models often rely on large-scale vision-language backbones and dense visual histories, imposing substantial computation and memory costs that hinder onboard deployment. We propose LightVLN, a lightweight history-aware aerial VLN framework that combines a compact 0.5B language backbone with compact representations of both historical and current observations. LightVLN compresses each historical frame into a single token using visual features already computed by the policy. It further introduces history- and instruction-conditioned local aggregation to reduce the current observation from 256 to 32 visual tokens while preserving navigation-relevant spatial information. With up to 16 historical frames, the policy uses at most 48 observation-derived tokens. On the public OpenFly dataset, LightVLN achieves 50.93% Test-Seen and 36.14% Test-Unseen success rates (SR), outperforming the evaluated 7B language-backbone baselines on most reported metrics. It also achieves 25.83% SR on AerialVLN-S Val-Seen. In a reconstructed unseen campus, we deploy LightVLN on a DJI M350 RTK with an external Jetson Orin NX 16 GB for closed-loop onboard-compute real-to-sim hardware-in-the-loop (HIL) evaluation, achieving 14.61 Hz model inference and 11.13 Hz end-to-end decision updates. These results demonstrate the effectiveness and efficiency of LightVLN for aerial navigation. 

I. I NTRODUCTION 

Aerial vision-and-language navigation (VLN) enables un-manned aerial vehicles (UAVs) to follow long-horizon natural-language instructions from visual observations in complex three-dimensional environments [1]. It requires the UAV to connect instructions with visual observations and predict a sequence of actions toward the navigation goal. The AerialVLN benchmark established a foundation for this task through simulated aerial environments, annotated navi-gation trajectories, and a cross-modal alignment baseline [1]. Subsequent platforms expanded the realism and scale of aerial navigation data, supporting the development of more advanced navigation models [2], [3]. Recent methods further improve spatial reasoning and long-horizon decision making through explicit spatial representations, semantic subgoals, grounded targets, and learned multimodal policies [4]–[8]. Aerial navigation models have increasingly adopted larger language backbones and richer visual histories. Video-based navigation models [9], [10] and aerial foundation-model poli-cies [3], [8], [11] use large pretrained multimodal backbones for visual grounding and action prediction. Meanwhile, long-horizon aerial navigation has motivated retaining informa-tion across observation sequences through selected-frame histories [3], [8], structured spatiotemporal memory [12], [13], and relevance-aware or causal history integration [11], [14]. These mechanisms provide access to historical visual information for subsequent navigation decisions. However, the use of larger language backbones and richer visual histories also brings substantial computation and memory demands at inference [9], [15]. Deploying aerial navigation models on resource-constrained UAV platforms remains challenging [15]. In particular, large backbones and extensive visual context increase computation and memory demands at inference. Recent deployment-oriented systems improve efficiency arXiv:2610.05024v1 [cs.CV] 4 Oct 2026 through optimized inference pipelines, lightweight action generation, shared perception, and fast–slow or asynchronous execution [15]–[17]. Complementary to these deployment-oriented techniques, we target a compact language backbone and compact representations of both historical and current observations. Lightweight aerial VLN therefore also requires reducing the intrinsic resource demands of the navigation policy while preserving its navigation capability. Designing such a policy poses two challenges: con-structing low-cost historical memory that remains useful for action prediction, and compressing the current observa-tion while preserving navigation-relevant spatial information. First, for historical memory, existing aerial VLN meth-ods typically control temporal redundancy and computation through keyframe selection or compact history representa-tions [3], [8], [13]. These strategies reduce memory cost by limiting the number of retained observations or com-pressing their representations. NativeMEM [18] addresses this trade-off by compressing each historical frame into a single action-supervised token, enabling substantially longer and denser visual histories. It constructs memory through a separately optimized visual-encoding path initialized from the policy’s vision encoder. Second, for current-view com-pression, existing methods reduce visual redundancy through learned-query bottlenecks, regional aggregation, or language-conditioned token selection [9], [19]–[21]. These meth-ods effectively compress the current observation but do not exploit navigation history. DreamFly [11] incorporates historical context to enhance current-view representations through causal memory, but does not target lightweight visual token compression or low-cost memory construction. These observations motivate an integrated lightweight design that combines low-cost historical memory with compact current-view representations. To address these challenges, we propose LightVLN, a lightweight history-aware aerial VLN framework that com-bines a compact 0.5B language backbone with compact representations of both historical and current observations (Fig. 1). Each historical frame is compressed into a single token using visual features already extracted by the pol-icy. For the current observation, history- and instruction-conditioned local aggregation reduces 256 visual tokens to 32 while preserving navigation-relevant spatial information. With up to 16 historical frames, the resulting visual context contains at most 48 observation-derived tokens. We evaluate LightVLN on the public OpenFly splits [3] and AerialVLN-S [1] and conduct extensive same-backbone ablations on OpenFly. We further reconstruct a campus environment and construct a 500-episode unseen evaluation set, where LightVLN is deployed on a DJI M350 RTK with an external Jetson Orin NX 16 GB for closed-loop onboard-compute real-to-sim HIL evaluation. The main contributions are: 1) We propose LightVLN, a lightweight history-aware aerial VLN framework that combines a compact 0.5B language backbone with low-cost historical memory and compact current-view representations. With at most 48 observation-derived tokens, LightVLN pro-vides a compact visual interface for aerial VLN with a substantially smaller language backbone. 2) We develop two complementary lightweight designs: single-token historical compression that reuses visual features already extracted by the policy, and history-and instruction-conditioned local aggregation that re-duces the current observation from 256 to 32 visual tokens while preserving spatial information relevant to navigation. 3) We evaluate LightVLN on OpenFly and AerialVLN-S and conduct extensive same-backbone ablations on OpenFly. LightVLN achieves 50.93% Test-Seen and 36.14% Test-Unseen SR on public OpenFly, out-performing the evaluated 7B baselines on most re-ported OpenFly metrics, and achieves 25.83% SR on AerialVLN-S Val-Seen. We further conduct closed-loop onboard-compute real-to-sim HIL evaluation in a reconstructed unseen campus, where LightVLN reaches 14.61 Hz model inference and 11.13 Hz end-to-end decision updates on Jetson Orin NX 16 GB. II. R ELATED WORK 

A. Aerial Vision-and-Language Navigation 

Existing aerial VLN methods broadly include structured reasoning and learned multimodal navigation approaches. Structured methods introduce explicit spatial or semantic rep-resentations to support navigation reasoning. STMR [4] con-structs spatial representations for language-guided reason-ing, while CityNavAgent [5] performs hierarchical semantic planning with global memory. LookasideVLN [6] incorpo-rates direction-aware reasoning, and Fly0 [7] uses persistent metric anchors for zero-shot navigation. Learned multimodal approaches directly predict navigation decisions from visual observations and language instructions. AerialVLN [1] es-tablishes an early cross-modal navigation baseline, while OpenFly-Agent [3] scales aerial VLN with pretrained mul-timodal models and historical observations. AeroAct [8] further integrates spatial, temporal, and embodied reasoning within a unified navigation model. 

B. Efficient Aerial VLN and Onboard Deployment 

Existing work improves the efficiency of aerial VLN through lightweight inference, decoupled decision making, and computation reuse. VLA-AN [15] combines lightweight action generation with an optimized inference pipeline for onboard deployment. FSD-VLN [16] adopts a fast–slow dual-system architecture, separating high-level semantic rea-soning from frequent navigation updates. OnFly [17] shares perception features and reuses memory across decision steps to reduce redundant computation and support real-time on-board execution.

E. Two-Stage Training 

We first obtain a well-trained single-frame Base policy with the 32-token current-view representation but without historical memory. Starting from this Base policy, we adopt a two-stage training strategy to learn stable single-token histor-ical representations. All stages use cross-entropy supervision over the demonstrated actions. 

Stage 1: memory representation learning. We freeze the well-trained Base policy and optimize only the historical tokenizer, memory projector, and MEM-BOS embedding. The 32-token current-frame pathway is retained, while the compressed historical tokens are introduced through the multimodal token interface in Eq. (6). After Stage 1, the his-torical tokenizer is frozen and used to generate the historical features cached for Stage 2. 

Stage 2: memory-augmented policy training. We train the final policy using the cached historical features. The historical tokenizer and visual encoders remain frozen, while all remaining trainable modules are jointly optimized. IV. E XPERIMENTS 

A. Experimental Setup 

Benchmarks and training inputs. Separate policies are trained on the released OpenFly and AerialVLN-S train-ing splits, using RGB images and instructions as inputs and demonstrated actions as supervision. OpenFly train-ing uses 100,221 episodes with 1,608,400 supervised step samples; AerialVLN-S training uses 1,157,437 supervised step samples. OpenFly [3] Test-Seen contains 1,392 public episodes from AirSim scenes 16, 18, 26, gz, sh, and 23, plus UE BigCity; Test-Unseen contains 404 episodes from UE SmallCity. AerialVLN-S uses the original release, simulator, annotations, and 333-instruction Val-Seen split [1]. 

Campus unseen evaluation set. We reconstruct an anonymized campus environment from DJI Mavic 3E ob-servations. DJI Terra performs pose estimation, dense recon-struction, meshing, and texture mapping; the metric textured model is imported into UE/AirSim with OpenFly’s cate-gorical action interface and motion settings [3]. The 500-episode campus unseen evaluation set allocates balanced quotas across five sub-regions and 53 verified goal land-marks. Collision-checked 3D routes have controlled intra-/cross-region composition, length, and maneuver complexity. Following the data-generation paradigm of OpenFly [3], routes and navigation instructions are constructed from dis-crete actions and key-view observations. The campus and its observations are reserved for unseen evaluation of an OpenFly-trained checkpoint. 

Metrics and comparisons. We follow the official OpenFly and AerialVLN-S evaluation implementations. We report navigation error (NE), success rate (SR), oracle success rate (OSR), and success weighted by path length (SPL) on OpenFly. On AerialVLN-S, we report NE, SR, OSR, and Success weighted by normalized Dynamic Time Warping (SDTW). Both benchmarks define successful navigation as stopping within 20 m of the goal, with collisions counted as failures [1], [3]. OSR measures whether the agent enters the 20 m goal region at any point during navigation. Campus evaluation follows the OpenFly protocol. Table I separates OpenFly-Agent’s released scores from our same-pipeline re-evaluation and groups six-scene AirSim-only results sepa-rately from the public setting used by DreamFly [11] and LightVLN. Table II groups LAG, STMR, CityNavAgent, and LookasideVLN, which use additional depth, panoramic observations, or odometry, separately from monocular RGB methods [1], [4]–[6]. FLOPs and latency are profiled on an RTX 4090. Latency is averaged over 500 synchronized inferences after 20 warm-up iterations. 

Implementation. We initialize from MiniVLA’s 

prism-qwen25-0.5b-hf checkpoint [25], using Qwen2.5-0.5B-Instruct [24], DINOv2 ViT-L/14 with four register tokens, and SigLIP ViT-SO400M/14-224 at 

224 ×224 resolution. The complete policy has approximately 1.276B parameters; 0.5B denotes the language backbone. Offline training and inference use BF16 for most parameters and FP32 for numerically sensitive parameters. Both datasets use separately trained eight-class action heads. For OpenFly, we exclude the two released action categories that are unused in the released trajectories, resulting in an eight-action policy space. All stages use an effective batch size of 256. Base, Stage 1, and Stage 2 are trained for 3, 1, and 4 epochs, respectively. The Stage 1 checkpoint is used to build the 1T cache, and the reported model uses the Stage 2 epoch-4 checkpoint. Training uses two H100 80 GB GPUs and LoRA [26] with rank r = 64 , α = 16 , and dropout 0.05. Learning rates are 10 −4 for the historical tokenizer and current-view visual projector, 5×10 −5 for the memory projector and MEM-BOS, and 2 × 10 −4 for LoRA, current-view aggregation, history-conditioning modules, and action modules, with 3% linear warm-up and cosine decay. 

Onboard setup and profiling. The closed-loop onboard-compute HIL platform couples a stationary, disarmed DJI M350 RTK carrying an E-Port-connected Jetson Orin NX 16 GB with a UE/AirSim host over USB Ethernet. AirSim supplies rendered observations and applies the Jetson’s pre-dicted actions through SetPose, confirming the virtual-pose update before the next observation. FLOPs and local latency cover complete policy inference. All latency measurements use batch size 1. Onboard inference uses TensorRT 10.3.0 and TensorRT-LLM 0.12.0 with module-specific mixed pre-cision and no model offloading. The exported policy agrees with the offline reference on all 500 action-check steps. Dense current and LightVLN use H = 16 , with the Jetson Orin NX configured in MAXN power mode. Latency is aver-aged over 500 measured frames after 10 warm-up steps. End-to-end latency includes image acquisition, communication, model inference, and virtual-pose update/confirmation.

V. C ONCLUSION 

We presented LightVLN, a lightweight history-aware aerial VLN framework built on a compact 0.5B language backbone with compact historical and current visual repre-sentations. LightVLN compresses each historical frame into a single token by reusing visual features already computed by the policy, and uses historical information to guide local aggregation of the current observation from 256 to 32 tokens. With up to 16 historical frames, the policy uses at most 48 observation-derived tokens. LightVLN achieves 50.93%/36.14% SR on public OpenFly Test-Seen/Test-Unseen and 25.83% SR on AerialVLN-S Val-Seen. Relative to the dense-current counterpart, the compact representation reduces full-model computation by 24.14% and RTX 4090 inference latency by 21.67%. On Jetson Orin NX 16 GB, LightVLN reaches 14.61 Hz model inference and 11.13 Hz end-to-end decision updates in the closed-loop onboard-compute HIL system.
